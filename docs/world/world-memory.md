## 不変の世界法則

本作の世界は物質だけでなく、**記述**によって成立する。記述に使われる根源的な言語を**呪歌**と呼ぶ。

| 用語 | 本作での意味 |
| --- | --- |
| 記述 | 存在、出来事、法則を定義する行為・情報。 |
| 書き換え | 既存の世界記述を変更すること。 |
| 再演 | 過去の世界記述を再実行し、失われた世界を一時的または継続的に存在させること。 |
| 再生 | 保存された世界記述を、新しい世界へ現実として定着させること。 |
| 呪歌 | 世界を記述・改変し得る根源的な言語。 |

過去世界には、滅亡した世界の再演、世界のやり直し、複数回の書き換えが起きた記録がある。本作はそれらを一つの根源法則から派生する現象として扱う。

## 万物の書と討伐の意味

【万物の書】は文章を読むだけの書物ではなく、人物、文明、生物、自然、戦争、災害、呪歌、世界改変を含む**世界記述を物語・ページとして保存できる存在**である。

主人公は白紙の新天地へ記述を転写するが、ページを直接世界にできない。そのため必ず次の工程を経る。

`ページ → 巨神獣として実体化 → 討伐 → 記述解放 → 新天地へ定着`

巨神獣は、万物の書に保存された「世界の記憶」が現実へ実体化した巨大存在であり、単なる怪物ではない。討伐は記憶を破壊する行為ではなく、器に凝縮した世界記述を新天地へ定着可能な状態へ解放する行為である。同一巨神獣を繰り返し召喚・討伐できるのは、同じ記述を再実体化し、追加転写するためである。

巨神獣の物語は、その世界を変えた一つの出来事。巨神獣の詩は、その物語本文から抜き出された一文とする。

## テラフォーミング

テラフォーミングは通常の惑星改造技術ではなく、**保存された世界記述を新天地の世界記述として定着させる行為**である。討伐により森林、河川、海、山岳、雪、気候、生態系が誕生する。

召喚Lvは実体化する世界記述量にも対応する。高Lvほど強い巨神獣となる一方、討伐時に定着する記述量も多く、テラフォーミング進行量・報酬が増える。

## 解放順と第15巨神獣

No.01〜14は、前の巨神獣を一度討伐すると次ページを解放する。No.14の初回討伐までに、過去7世界由来の環境記述が新天地へ配置される。

ただしこの時点では新天地は「過去世界の寄せ集め」に過ぎない。No.01〜14を初回討伐した時、万物の書に過去になかった新しいページを生成し、No.15を解放する。

No.15は過去7世界の記憶を直接再生した存在ではなく、**新天地そのものが初めて生んだ世界の記憶**である。討伐により、森林と河川と海、雪山と河川、火山と鉱物、気候と四季、植物と動物が相互に接続される。ここで初めて星は過去世界の複製ではない、新しい一つの世界になる。

したがってNo.01〜14は「過去を再生する巨神獣」、No.15は「未来を誕生させる巨神獣」として扱う。

## 箱庭、家具、交流の接続

各巨神獣のテラフォーミング結果は2Dワールドマップだけでなく箱庭エリアへ反映する。再生環境に応じて、配置可能家具、クラフト素材、ヒロインの待機・利用行動、主人公との交流、恋人専用交流が増える。

テラフォーミングの主要なゲーム的報酬は、**ヒロインたちと過ごせる世界が増えること**である。家具や環境を未解放にしたことで、メイン物語や恋人イベントを永久に阻害してはならない。

## 実装データ要件

```text
WorldLineDef { id, name, theme, environmentTags[] }
ColossusDef { id, provisionalName, worldLineId?, order: 1..15,
  prerequisiteColossusId?, isIntegrationBoss, environmentTags[],
  gardenUnlockIds[], furnitureRecipeIds[], materialRuleIds[] }
```

- No.15は`worldLineId=null`、`isIntegrationBoss=true`、`prerequisiteColossusId`ではなくNo.01〜14全初回討伐を解放条件とする。
- `environmentTags`をテラフォーミング、箱庭、家具、交流が共有参照する。表示名で環境を結合しない。
- 各巨神獣の24詩、3章、部位4〜6、大技、Lv45最強技は[戦闘・詩・ヒロイン詳細仕様](../systems/battle.md)に従う。

## 神獣の歌・物語の提示（動画観測からの独自反映）

参考動画の確認から、巨神獣の図鑑・物語は一つの見開きに「対象そのもの」と「章への入口」を併置する構造が、収集状況を把握しやすいと分かった。newASTERでは固有の文章、章名、ページ意匠を流用せず、次を独自仕様として実装する。

- 左ページ：巨神獣の肖像、記憶元、環境への定着内容、部位進捗、詩の収集数を置く。
- 右ページ：3章の見出しと`0/8`〜`8/8`の収集状況を置く。章が解放されるまで本文は表示しない。
- 未解放章は黒インクや欠けた記述のような抽象演出で覆い、本文・未公開詩・未公開数値を出さない。
- 戦闘中の歌は、該当巨神獣の物語本文から切り出す一文を`PoemDef`として記録し、戦闘結果で新規取得のみを表示する。
- 章を開くと、万物の書の通常の対象ページめくりではなく、独立した「本として読む」ページ送りへ移る。

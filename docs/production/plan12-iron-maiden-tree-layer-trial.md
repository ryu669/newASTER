# アイアンメイデンの神器装飾・分離試作

2026-10-11。共通の木へキャラ別の透過装飾だけを重ねる方式を試作した。ゲーム本体への組み込み・キャラ完了判定はまだ行っていない。

## 参考画像を受けた再検討

ユーザー提供の `kyoshin-to-seijyo_05.jpg`、`0e6208e0.png`、`ed277842.png` を構成参考として確認した。原作画素を製品素材へコピーせず、新規の共通素材を制作する。

前の試作は合成方法の確認には使えるが、見た目の基準としては不採用。ベクターの太い曲線は自然な木に見えず、一体の大きな装飾を3箇所へ置く方法も、細かな意匠が散るイメージから外れていた。以下を次の制作基準とする。

| 層 | 改定した内容 |
| --- | --- |
| 共通の木 | 樹皮の凹凸、太い幹、自然に曲がる大小の枝、細い枝先、地面へ広がる根がある描き込まれた木の画像。機械的なY字や金属の配線にしない。左右完全対称にせず、ノードを置ける余白を残す。 |
| 共通の葉 | 小さな葉を枝先へ分散する。幹の質感を保ったまま葉と淡い光を配色し、キャラの色を表す。木全体を単色で染めて樹皮を消さない。 |
| 専用の小装飾 | キャラごとに小さな葉飾り、宝石、留め具など数種類を透過素材として生成する。単体を配置できるよう分け、大きな一体の紋章・花輪を主役にしない。 |
| 操作ノードと文字 | 木の枝に合わせた共通13位置を採用し、装飾より手前に置く。ノード位置をキャラごとの装飾に合わせて動かさない。 |

木の構図が決まった時点で13位置を一度合わせ、その木と配置を共通化する。以前の図形的な構図に自然な木を無理に押し込めない。根1＋3ルート×4段という育成構造と、枝の自然な形状を両立させる。

アイアンメイデンの試作案は、暗い樹皮の木、銀灰の小葉、黒鉄の小さな留め具、深紅の小宝石、少量の金色。専用装飾は3〜4種類をまず作り、枝の分岐・枝先・根元へ大小を変えて10〜16箇所程度に散らして比較する。これは初期配置案であり固定数ではない。根元だけへ集めず、等間隔・同じ向きの反復も避ける。ノード、名前、Lv、選択の光を妨げる箇所には置かない。

参考画像から、キャラ別生成の対象を木全体へ戻す必要はないと判断した。自然な木と葉を共通化し、小装飾だけをキャラ別に作る方針を維持する。確認順は、共通の自然な木1点 → 13ノードを重ねた表示 → 小装飾の単品 → 分散配置したアイアンメイデンの表示。木と装飾を一度に完成させようとしない。

自然な木と小装飾3点の第2試作を制作した。`game/art-source/equipment-tree-layered-trial-v2/` に、共通の木、銀葉、深紅の宝石、黒鉄の留め具の原本を無加工で保存。装飾は15箇所へ散らし、13ノードは共通配置にした。比較画面でノード選択による武器名表示も確認した。全プロンプト・生成元・原本ハッシュは同フォルダの `generation.json` に記録。1920×1080のブラウザー比較を目視確認した試作であり、Unity Playerへの組み込みと受入れは未実施。

以下は第1試作の記録として残す。

## 第3試作：装飾の拡大と開花

`game/art-source/equipment-tree-layered-trial-v3/preview.html` に開花試作を保存した。既存の小装飾は1.85倍に拡大し、木と13ノードの配置は保持した。本人のイメージカラーである深紅の花を独立した透過素材として生成し、原本無加工で保存している。生成方式・指示・原本ハッシュは `generation.json`。

根は初期開放なので開花対象外とし、根のみでは0輪。花は開放済みの非ルートノードの左右下に2輪ずつ置く。ノードを手前に表示し、花が文字と操作を遮らないようにする。各ルートの開放に対応して2輪ずつ増え、各ルートⅡまでで12輪、全開放で24輪。花数は試作用の配置値で、能力値には関係しない。ノードLv強化とは区別し、解放IDによって開花範囲を決める設計とする。

中央の木はルート別スライダーとノード選択で開放段階を変更できる。根のみ・各ルートⅡ・全開放の比較、ルート独立、親ノードを飛ばす開放の拒否、武器名の表示を自動操作で確認し、1920×1080の比較画像を目視した。木 → 専用装飾 → 開花・蕾 → 操作ノードと文字の重ね順で、花が操作を遮らない。ヒロイン別の花色は花素材・配色の設定として分離する。

最大開放で参考画像のように大量の葉が茂るよう、葉の独立配置を樹冠全体へ増やした。銀灰の葉素材 `silver-foliage.png` は原本無加工で再利用する。葉は木の後ろ、幹・枝と操作ノードは手前に描いて形と操作性を保つ。ルート別の開放段階に応じて下の枝から枝先へ広がり、根のみ0組・各ルートⅡで324組・全開放692組。根元には追加しない。花は開放済みノードの周りだけに配置し0/12/24輪。1920×1080で比較表示と親順の開放操作を確認した。

これはブラウザーでの試作。実セーブ、素材消費、Unity Playerへの接続とキャラの受入れは未実施。根のみ開放と全開放の比較を試作上で確認したことを、ゲーム本体での進行確認と混同しない。

## 第1試作の保存内容

素材は `game/art-source/equipment-tree-layered-trial-v1/` に保存した。

- `common-tree.svg`：共通構図のベクター試作。根・3枝を固定し、銀灰と黒の配色を指定。今後のキャラでも同じ形状を使う。
- `iron-maiden-decoration-v1.png`：画像生成による専用装飾1点。銀の葉、黒鉄の唐草、赤い宝石、小さな炎の意匠。人物・木・ノードを含まない。生成原本の画素は無加工。
- `layout.json`：共通13ノードと装飾3箇所の配置。1点の装飾を縮尺・回転を変えて再利用する。
- `preview.html`／`comparison.png`：配色だけの木と装飾追加版の比較。ノード表示を切り替えて確認できる。

重ね順は共通の木 → 専用装飾 → 操作ノードと文字。1920×1080のブラウザー試作で、画像読み込み、左右それぞれ13ノード、装飾の配置と文字の視認性を確認した。Unityの既定起動画面の受入れとは区別する。

試作の結果、木の構造とノードを変えず、専用装飾1点でキャラの配色とモチーフを足せることを確認した。木の描き込みは現状のベクター試作から共通素材として仕上げる余地がある。専用装飾の量・位置は木の仕上げ後にも独立して調整できる。

従来の人物入り神器PNGは不採用のまま保持する。この試作を理由に既存の神器画像審査や4人の受入れ状態を自動で合格に変更しない。


## ゲーム本体への反映

アイアンメイデンの神器画面に分離描画を実装。`UI/WeaponTrees/iron-maiden.json` が共通木・専用装飾・葉・花とノードの位置を管理し、従来の人物入り神器画像はこの画面では使用しない。ノードID・素材・能力・装備・Lv・セーブ形式は維持する。葉と花は保存済みの各ノードIDの開放有無で判定し、装備中ノードやLvには連動させない。根のみでは追加の葉と花はゼロ。木を葉の手前、操作ノードを花の手前に描く。

今回の接続対象は試作を確認したアイアンメイデン。ほかのヒロインの色と専用装飾の受入れは別途行う。`LayeredWeaponTreePreviewBuild` は専用の診断用出力先だけを使用し、量産画像の審査・通常配信版への昇格を行わない。


本体接続の確認結果：確認用Windows Playerの根のみ・各ルートⅡ・全開放をデフォルト1920×1080で撮影し、実画面を目視確認した。各段階を専用セーブへ保存して読み直し、異なる3枚の描画を確認。葉は木の枠内、花は開放ノードの左右、根は追加開花なし。13アンカーの不透明な枝への配置と操作領域の非重複をUnityビルド検査で確認。回転は本の拡大変換と干渉するため本体では行わず、枠内の座標で直接描く。通常配信版への昇格と他ヒロインへの展開は含まない。

検証記録：`tmp/plan12-batch/layered-tree-build-final.log`、`tmp/plan12-batch/layered-tree-player-final.log`、`tmp/plan12-batch/layered-tree-player/stage-{0,2,4}.png`。再確認は `tools/validate-layered-weapon-tree-player.ps1` を使用する。確認用画面は撮影時に表示する必要があり、非表示起動の黒画像を合格扱いしない。


## 葉の簡略化と追加レビュー

2026-10-11：細かな葉脈・銀の光沢が強かった葉を、簡単な輪郭と控えめな陰影の `silver-foliage-simple-v2.png` へ差し替えた。生成原本は無加工で保持し、表示時の不透明度を48%にする。葉のまとまりを6.4〜8.5%幅へ少し小さくし、最大692組を維持して軽さと茂りを両立させる。左右反転による向きの変化を追加。開放段階の境目に小さなばらつきを設け、水平の切れ目が揃いすぎないようにした。途中Ⅱは323組、花は従来の0/12/24輪のまま。元の濃い葉は履歴として残す。

追加レビュー：葉の白さ、同方向の繰り返し、途中開放の水平境界は今回修正する。残る改善候補はノードの大きな黒い背面とラベルが枝・花を隠す点。操作範囲と文字の読みやすさを保ちながら背面を小さくする案が適切で、ノードの移動やセーブIDの変更は不要。樹冠はまだ共通の楕円構図であり、他ヒロイン展開時には色と装飾の組合せを個別に確認する。

簡略葉版は確認用Playerの標準1920×1080で途中・最大の見え方を確認済み。根/途中/最大の保存・再読込と別描画は `tmp/plan12-batch/simple-leaf-player.log`、ビルドは `tmp/plan12-batch/simple-leaf-build.log` が合格。葉の生成元とプロンプトは第3試作 `generation.json` の `simpleFoliage` に記録。


## 丸枠ノードと木の下移動

ノードの大きな四角い背面を廃止し、金色の二重円と8方向の小飾りを持つ丸枠へ変更した。中央の効果アイコンは38pxへ縮小し、花は丸枠の左右に残す。Lv・取得条件のラベルと元のクリック範囲は維持する。選択中と装備中も丸枠の色で示し、四角い装備枠・選択ダイヤはこの木では使用しない。

木の描画領域を34px下げ、木・葉・装飾・花・ノードを同じ矩形に連動させた。拡大率は維持し、最大開放時にも上の「攻撃・守護・技巧」と葉の間に余白を確保。根元も枠内に収まることを標準1920×1080のPlayerで確認した。根/途中/最大の保存・再読込・別描画が合格（`tmp/plan12-batch/round-node-player.log`）、Unityビルド合格（`tmp/plan12-batch/round-node-build.log`）。前節のノード背面に関する改善候補はこの変更で対応済み。

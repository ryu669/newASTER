# Plan11-2 箱庭生活システム 実装仕様 v0.1

## 1. 目的

既存の「家具を配置してヒロインを置く箱庭」を、

**プレイヤーが作った新天地で、ヒロインたちが実際に生活しているように見える生活空間**

へ拡張する。

基本ループは、

`11-1で世界発展`
→ `庭の景観・家具・現象解放`
→ `家具クラフト/配置`
→ `ヒロインが自律生活`
→ `家具利用・Social`
→ `生活催事・生活発見`
→ `生活記録・記念家具`
→ `庭をさらに作り込む`

とする。

箱庭による戦闘能力ボーナス、放置報酬、リアル時間待機は導入しない。

---

# 2. 既存資産の扱い

以下を維持する。

- 既存9庭
- 既存10家具
- 既存`gardenId`
- 既存家具`instanceId`
- 正規化配置座標
- footprint衝突
- 家具在庫
- 家具配置/撤去
- 人物配置
- 人物の複数庭重複禁止
- 戦闘編成と庭配置の独立

既存セーブから家具・人物配置を失わない。

11-2では既存データへ生活用定義を**追加**する。

---

# 3. 庭の機能分類

既存9庭それぞれに以下のいずれかの機能タイプを割り当てる。

既存表示名・IDは変更しない。

| タイプ | 主領域 | 用途 |
|---|---|---|
| `central` | 全＋文明 | 新天地中心・大型催事 |
| `flower` | 生命＋光 | 花・園芸・お茶 |
| `forest` | 生命＋夜 | 森林・散歩・休息 |
| `lakeside` | 水＋天 | 水辺生活 |
| `highland` | 天＋光 | 景色・キャンプ |
| `stargazing` | 夜＋天 | 星見・夜間生活 |
| `hotspring` | 地＋水 | 温泉・休息 |
| `snow` | 水＋天＋地 | 雪・寒冷生活 |
| `city` | 文明＋可変 | 都市生活 |

**実装時には既存9庭を確認して最も近いタイプへ対応付ける。**

---

# 4. 中央庭

`central`は新天地全体を代表する庭とする。

特定領域の景観ではなく、

**7領域の現在状態から合成**

する。

例：

生命5＋文明3
→ 緑の多い生活街

夜7＋文明7
→ 永夜ネオン都市

生命7＋文明7
→ 植物と建築が融合した都市

中央庭をお気に入り庭の初期候補とする。

---

# 5. Terraform連携

各庭は11-1の、

- `currentLevel`
- `activeDeepRecordId`
- `activeExtremeId`
- 世界現象

を参照する。

表示構造：

```text
GardenBase
+ TerraformLayer
+ ExtremeLayer
+ DeepRecordModifier
+ WeatherLayer
+ WorldPhenomenonLayer
+ Furniture
+ Heroine
+ Foreground
```

Terraform変更で家具配置座標を変更しない。

Lv6/7になっても既存家具を自動撤去しない。

---

# 6. 過剰再生時の生活圏

Lv6/7環境でも庭では通常生活可能とする。

設定上、

**アステリアの世界統合記述が生活圏を局所安定化している**

とする。

したがって、

- ダメージ
- 寒冷ペナルティ
- 熱ペナルティ
- 好感度ペナルティ
- 戦闘能力変化

は発生しない。

住みにくさは景観・環境音・人物リアクションで表現する。

---

# 7. 自律生活AI

共通生活AIを全ヒロインで使用。

人物専用AIクラスは禁止。

基本カテゴリ：

```text
Idle
Move
Scenery
Furniture
Social
Special
```

`Special`だけ人物実装・催事・イベントから追加可能。

---

# 8. 基本Weight

初期値：

| Action | Weight |
|---|---:|
| Idle | 30 |
| Move | 20 |
| Scenery | 15 |
| Furniture | 20 |
| Social | 15 |

実行不能Actionを除外後、再正規化して抽選。

人物固有補正はヒロイン実装側。

未定義なら共通値を使用。

---

# 9. 行動時間

初期値：

| 行動 | 時間 |
|---|---|
| Idle | 4～10秒 |
| Scenery | 8～20秒 |
| Furniture | 10～30秒 |
| Social | 15～40秒 |
| Move | 距離依存 |
| Special | 定義依存 |

行動間に0～5秒のTransition Idleを許可。

seed付き乱数を使用しテスト再現可能にする。

---

# 10. 行動偏り防止

各Agentにセッション内だけ、

```text
recentActions[3]
cooldowns
```

を保持。

直前と同カテゴリ：

`Weight × 0.2`

2回前：

`Weight × 0.5`

初期Cooldown：

- 同一家具：30秒
- 同一Social相手：60秒
- 同一Scenery：45秒

これらは保存しない。

---

    preferredEnvironmentTags
    specialBehaviorIds

を提供可能。

11-2はProfileなしでも完全動作すること。

ヒロイン固有値・台詞・嗜好は**ヒロイン実装側で決定**する。

# 14. Interactionと表示素材を分離

ゲームロジックでは、

`interaction.read`

だけを扱う。

表示側が、

専用人物演出
→ 共通演出
→ 汎用ポーズ
→ 静止表示

の順で解決。

人物専用素材がなくてもInteraction自体は成立させる。

---

# 15. InteractionSlot

家具へ、

```text
InteractionSlot {
    id
    interactionTags[]
    localPosition
    facing
    capacity
    playerSlot
}
```

を追加。

家具の移動・反転に追従。

同一slotの不正重複利用を禁止。

---

# 16. 主人公Slot

`playerSlot=true`を許可。

主人公モデルは表示しない。

ヒロインが空席/画面方向へ話しかけることで、

**主人公もその生活に参加している**

ことを表現する。

特に、

- お茶会
- 花見
- 温泉
- 星見
- 食事

で使用する。

---

# 17. 家具到達

2D自由配置を維持。

高度なNavMeshは必須にしない。

Gardenの移動可能領域と家具footprintから簡易移動経路を解決。

InteractionSlotへ到達不能なら候補から除外。

編集モードでは、

> 到達不能

を警告表示する。

配置そのものは装飾用途を考慮して許可する。

---

# 18. ReservedZone

庭ごとに、

- 出入口
- 必須通路
- 重要SceneryPoint

をReservedZoneとして設定。

新規家具配置を禁止。

旧セーブ家具が重なっている場合は削除せず警告する。

---

# 19. SceneryPoint

各庭3～5個を基本。

```text
SceneryPoint {
    id
    interactionTags[]
    slots[]
    environmentCondition
}
```

家具と同じInteraction候補として扱う。

Terraformによって有効/無効を変更。

---

# 20. Social

通常Socialは**最大2人**。

AがBへInteractionを要求。

Bが参加可能なら、

```text
InteractionSession
```

を生成。

基本遷移：

`Approach → Face → Interaction → Reaction → End`

Session中の人物を別Sessionへ参加させない。

---

# 21. 3人以上

通常AIでは扱わない。

3人以上は**生活催事**で扱う。

これにより通常AIを単純化する。

---

# 22. 家具からSocialへの遷移

複数人家具で、

A利用中
→ Bが空slotへ参加
→ 条件成立
→ Social

を許可。

景色でも同様。

これにより、

**家具/景色 → 人が集まる → 会話**

を自然発生させる。

---

# 23. SceneTemplate

庭を開いた瞬間に全員棒立ちすることを禁止。

初期生活スナップショットを生成する。

テンプレート：

### calm
Idle・Scenery中心。

### lively
Move・Furniture・Social多め。

### gathering
大型家具周辺。

### solitary
一人行動中心。

テンプレート選択後、人物・家具・景色へ割り当てる。

---

# 24. 画面外AI

**実行しない。**

現在表示庭の人物だけリアルタイムAgentを生成。

別庭は、

- assignedGardenId
- 固定/優先等の設定

だけ保持。

庭を開いた時に生活スナップショットを生成する。

オフライン経過時間シミュレーションなし。

---

# 25. 表示人数

標準：

**8人**

GardenDefで、

```text
maxVisibleOccupants
```

を変更可能。

性能に応じ6～10程度へ個別調整可能。

200人超を同時表示しない。

---

# 26. 人物配置モード

各ヒロインについて、

### Fixed
この庭へ固定。庭内では自由行動。

### Preferred
自動配置時に優先。

### Auto
ゲーム側が配置。

### Hidden
箱庭自動表示対象外。

を設定可能。

同一人物の別形態・衣装を同時配置しない既存規則を維持。

---

# 27. ポーズ固定

鑑賞用として任意。

人物を特定位置/Interactionへ固定。

通常自律移動を停止。

他人物からSocialを受ける設定はON/OFF可能。

---

# 28. 自動配置優先順

表示上限を超える場合、

1. Fixed
2. Preferred
3. お気に入り人物（設定ONの場合）
4. Auto

で選択。

同じAuto人物ばかりにならないようvisitCounterを使用してローテーション。

---

# 29. 時間帯

リアル時計と連動しない。

```text
morning
day
evening
night
```

4段階。

プレイヤーが無料で変更可能。

自動進行なしを初期仕様とする。

Terraformの永夜/永昼とは別管理。

---

# 30. 天候

通常天候：

```text
clear
cloudy
rain
snow
```

Terraform状態から自動Weightを決定。

設定：

**自動天候 ON/OFF**

OFFなら解放済み通常天候を固定。

---

# 31. 世界現象

11-1で解放。

例：

- 花吹雪
- 蛍
- 流星群
- オーロラ
- 雷雲
- 海上花火
- 光晶雨
- ネオン祭

通常天候とは別レイヤー。

生活AIのScenery Weightへ影響可能。

能力効果なし。

# 32. coveredタグ

zone/家具に、

`covered`

を設定可能。

雨・雪時にはcovered場所のWeightを上昇。

人物ごとの反応差は人物実装側。

# 33. 生活催事

初期10種類を固定。

1. ピクニック
2. お茶会
3. 花見
4. 星見
5. 温泉
6. キャンプ
7. 花火
8. 食事会
9. 雪遊び
10. 水遊び

催事は繰り返し可能。

報酬通貨なし。

---

# 34. 催事参加人数

最大8人。

**おまかせ**
または
**人物指定**

を選択。

催事中は通常ActionPoolから、

`ActivityActionPool`

へ切替。

同じ催事でも人物が異なる行動をする。

---

# 35. 催事終了

プレイヤーが任意終了可能。

通常終了時は短い`activityEnding`を実行してから通常AIへ。

庭切替・ADV・戦闘開始では即時破棄可能。

---

# 36. 生活発見

三種類。

### WorldDiscovery
世界現象・Terraform由来。

### CommonLifeDiscovery
11-2共通。

### HeroineLifeDiscovery
人物実装側。

共通生活発見は**初期30件**を目標とする。

---

# 37. 発見確率

極端な低確率は禁止。

条件成立中は未発見項目のWeightを上げ、

**数回の訪問/催事で自然に発見可能**

にする。

未発見項目には生活記録でヒントを表示。

---

# 38. 発見の再演

初回発見後も同じ生活シーンは通常AIから再発生可能。

初回のみ、

> 新しい生活記録

通知。

以後通知しない。

---

# 39. 生活記録

万物の書、

**新天地 → 生活記録**

から閲覧。

保存：

- discoveryId
- 発見済み
- 関連庭
- 関連環境

能力値・コンプリート報酬なし。

人物専用生活記録は人物実装側。

---

# 40. 記念家具

一部生活発見で家具レシピを解放。

例：

- 星図
- 桜ランタン
- 貝殻飾り
- 湯上がり用品

戦闘能力なし。

家具そのものではなく**レシピ解放**を基本とする。

---

# 41. 家具クラフト

即時完成。

リアル待ち時間なし。

TPは使用しない。

初期素材量：

| 家具 | 素材量目安 |
|---|---:|
| 小型 | 1～3 |
| 中型 | 3～6 |
| 大型/催事 | 5～10 |
| 極相 | 高Lv素材を個別設定 |

具体素材は家具定義側。

---

# 42. 家具制作数量

クラフトUI：

`1 / 5 / 10 / MAX`

を提供。

同一操作で複数制作可能。

---

# 43. 環境と家具

環境タグ不一致だけで配置禁止しない。

例：

サイバー都市に木製ベンチ
→ **許可**

物理的に不可能な配置だけ拒否。

プレイヤーの景観制作自由を優先。

---

# 44. 家具レイアウトセット

各庭**5セット**を初期上限。

保存内容：

```text
FurnitureLayoutPresetEntry {
    furnitureDefId
    x
    y
    orientation
}
```

instanceIdには依存しない。

適用時に在庫を割り当てる。

不足時は不足数を表示し、勝手にクラフトしない。

- 大グリッド
- 吸着

# 48. プレイヤー操作

人物クリック時の基本メニュー：

- **話す**
- **様子を見る**
- **配置**
- **人物詳細**

人物イベントが`available`の場合のみ、

- **話したいことがあるようだ**

を追加表示する。

通常の「話す」から長編ADVを突然開始しない。

---

# 49. 「話す」

短い箱庭会話用。

人物専用`GardenBarkSet`が存在する場合はそこから解決する。

人物専用文章が存在しない場合、**汎用文章を勝手に人物へ喋らせない**。

その場合は、

- 表情
- 手を振る
- こちらを見る
- 軽いジェスチャー

などの汎用リアクションだけで成立させる。

キャラクター性を共通台詞で破壊しない。

---

# 50. 「様子を見る」

現在の生活行動を短文で表示する。

例：

> 湖を静かに眺めている。

> 二人で何か話しているようだ。

> 花壇の様子を見ている。

これはキャラクターの台詞ではなく、**システム側の状況説明**。

人物固有版があればヒロイン実装側から上書き可能。

---

# 51. 人物イベント入口

箱庭はイベントの**発見・入口**として利用できるが、イベント進行そのものは11-3/ADVへ渡す。

状態：

```text
locked
available
reading
read
```

`available`になったイベントは、その後、

- 庭を変更
- 家具を撤去
- Terraformを変更
- 時間帯を変更

しても消失させない。

永久取り逃し禁止。

---

# 52. 恋愛システムとの境界

11-2は以下を変更しない。

- 好感度
- 恋人状態
- 恋愛イベント解放
- 誓い
- 個人ストーリー進行

11-2は条件参照と入口表示だけ可能。

人物を庭へ長時間置くことで自動的に好感度が増えることも禁止する。

---

# 53. 戦闘との境界

庭配置と戦闘編成は完全独立。

庭にいる人物も即座に出撃可能。

出撃時に庭配置を解除しない。

戦闘終了後も庭割当を維持。

世界観上の厳密な同時存在よりゲーム操作性を優先する。

---

# 54. ADVとの境界

ADV開始時：

1. 現在のGarden Sessionを終了
2. 箱庭の瞬間AI状態は保存しない
3. ADVへ遷移

ADV終了：

1. 箱庭へ戻る
2. 新しいSceneTemplateを生成
3. 生活再開

イベント開始前の立ち位置を完全再現する必要はない。

---

# 55. 鑑賞モード

ゲーム内画像保存機能は**実装しない**。

PC/OS側のスクリーンショット機能を使用する。

箱庭側では、

### 鑑賞モード

のみ提供。

機能：

- 通常UI非表示
- 名前表示非表示
- AI継続/一時停止
- 装飾フレームON/OFF
- 通常UIへ戻る

カメラ機能を別システムとして肥大化させない。

---

# 56. 装飾フレーム

能力効果なし。

初期カテゴリ案：

- 万物の書
- 花
- 森
- 水
- 星
- 雪
- 黄金
- 蒸気
- サイバー
- 七極創世

Terraform・生活発見等で解放可能。

スクリーンショット自体はPC側で行う。

---

# 57. 環境音

庭には、

```text
baseAmbientId
```

を持つ。

さらに、

```text
terraformAmbientId?
phenomenonAmbientId?
```

を重ねる。

最大3環境レイヤーを基本とする。

例：

森林庭
＋生命Lv6
＋雨

なら、

森林環境音
＋深森環境音
＋雨音

となる。

---

# 58. BGM

28極相すべてに専用BGMは要求しない。

基本は庭/生活向けBGMを共有し、

**環境音でTerraform差を表現する。**

特殊な本編イベント・人物イベントはADV側のBGM定義を使用。

---

# 59. 生活SE

候補：

- 足音
- 着席
- 本
- 食器
- 水
- 家具操作

同種SEが同時大量再生されないよう制限する。

表示中8人全員のSEを常時鳴らさない。

画面上の重要Interactionを優先する。

---

# 60. アクセシビリティ

既存設定の、

- 揺れ軽減
- フラッシュ軽減
- BGM音量
- SE音量

を箱庭にも適用。

Lv6/7で、

- 雷
- 強風
- 発光
- ネオン
- 激しい粒子

が増えてもアクセシビリティ設定を無視しない。

# 61. 「穏やか表示」

# 86. 生活発見の抽選

条件成立だけで即発生させるものと、自然発生を待つものを分ける。

```text id="7z97tx"
triggerMode =
immediate
weighted
```

初回の重要な発見は`immediate`。

日常シーンは`weighted`。

weightedでも極端な低確率は禁止。

初期最低Weightを**20%相当以上**とする。

連続不発補正を入れ、5回条件成立して未発見なら次回確定としてよい。

# 117. エラー時の原則

11-2では生活演出の問題によって**ゲーム本編を停止させない**ことを原則とする。

例えば、

専用座り画像欠落
→ 汎用表示

家具slot利用不能
→ 別Action

SceneryPoint利用不能
→ Idle

SceneTemplate構築不能
→ calm

Social成立不能
→ 一人行動

と安全にフォールバックする。

ただし正式定義そのものが壊れている場合は開発検証でエラーにする。

# 118. 「演出エラー」と「データ破損」を区別

### 演出エラー

例：

- 家具満席
- 到達不能

ゲーム続行。

### データエラー

例：

- furnitureDef不存在
- gardenId不存在
- 同一instance二重配置

- ID重複

保存確定を拒否。

この区別をログにも残す。

# 120. 生活発見トランザクション

```text id="20ufzo"

    transactionId
    discoveryId

    contextSnapshot
    grantedRecipeIds[]
}
```

# 121. 記念家具レシピの二重取得

# 122. 催事状態は原則保存しない

催事中にゲーム終了した場合、

再起動後に催事途中から再開しない。

庭の通常生活状態から開始。

理由は催事に費用・限定報酬・失敗条件が存在しないため。

保存複雑性を増やす必要がない。

# 123. 鑑賞中の終了

鑑賞モードでゲームを終了しても、

再起動時は通常UI表示。

`鑑賞モード中`

そのものは保存しない。

選択中フレームだけ保存可能。

# 124. 編集途中終了

確定前に、

- ゲーム終了

- 強制終了

未確定配置を自動保存しない。

# 152. 11-2最終コンセプト

11-2で目指すのは、

**「ヒロインを配置したから動く庭」ではなく、プレイヤーが覗いた時にはすでに生活が存在している庭**

です。

11-1で、

> 世界を作る

11-2で、

> その世界に生活が生まれる

11-3以降で、

> その生活の中で主人公との関係が深まる

という三段構造にします。

したがって11-2ではシミュレーションの複雑さより、

**家具を使う、景色を見る、誰かと話す、時々こちらを見る、催事で集まる**

という少数の行動を自然に組み合わせることを最優先にします。

これで11-2は**実装に渡せる仕様としてほぼ完結**です。次段階はこの仕様を文書化して実装へ回すか、続けて **11-3「好感度・恋愛・誓い」** のゲームデザインを詰める段階です。

## 目的と適用条件

計画8で成立した一周を、初期5人・固有15巨神獣・正式物語と箱庭へ広げ、ゲーム起動から終了まで統一された正式版の画面品質に仕上げる。今回のユーザー指示により、起動・タイトル・各種画面UIの豪華化を計画9の必須成果物に追加する。

動作・数量は[ゲーム要求](../requirements/game.md)、表示は[2D表現要求](../requirements/presentation.md)、保存は[保存契約](../systems/save-and-migration.md)を優先する。[計画8の検証範囲変更](plan8-verification-scope.md)を継承し、追加性能測定・そのための負荷確認は実施しない。実操作は最大5操作、聴取は合計15秒以内のBGM一箇所と効果音一つに限定する。未測定の性能や全編の聴感を保証しない。

13ジョブは要求として保持する。初期5人で未登場のジョブを完成扱いにせず、9-1で現行のジョブ別仕様・実装との不足を整理する。追加人物数を黙って増減せず、初期公開対象と継続制作対象を台帳に明記する。未解決の必須要求があれば公開ゲートを未完了に残す。

## 豪華UIの制作方針

デザイン案は「記憶を収めた豪華な魔導書」。深い藍の背景、象牙色の紙、控えめな金箔、世界別の差し色、革表紙・栞・重なる紙、人物と巨神獣の大きな絵を組み合わせる。色の最終値は9-2の見本で決める。通常画面は美術を広く見せ、必要情報を開く。選択と操作結果は装飾の輝きだけに頼らず、文字・輪郭・アイコンでも示す。

共通部品は表紙／ページ、見出し、栞、主操作／補助操作ボタン、カード、資源と費用、ゲージ、説明、一覧、スクロール、確認、結果、通知、保存状態、ローディング、エラー。通常・選択・押下・無効・不足・保存待ちの各状態を用意する。日本語フォント、長文折返し、数字の整列、余白、画像比率、操作音を統一する。720pを下限として1080pでも確認する。

演出の初期案はボタン応答0.08〜0.15秒、パネル開閉0.15〜0.25秒、めくり／裏返し0.25〜0.45秒、タイトル導入2〜4秒。これは制作時の採用候補であり測定済みの性能値ではない。導入と報酬演出は省略可能にし、演出簡略化の設定を設ける。状態は一度だけ確定し、スキップ・連打で報酬や遷移を二重処理しない。

## 制作・取り込み・保存の契約

素材ごとに対象ID、用途、版、原画／編集元、出力、権利、hash、candidate／採用／再制作、確認画像を記録する。部位を統合して破壊演出を失わせない。表情差分・透過縁・切抜き・日本語文字・既存角冠の重なりも再審査する。全編音声、歌唱、Live2D／Spineは未確定のため必須工数へ自動追加せず、静止画・差分・効果で成立させる。

UIはCoreの確定結果を表示し、HP・資源・詩・報酬を直接変更しない。装飾やスキップで乱数を再消費しない。既存所持とreceiptを保持し、正式本文への切替で取得詩を削除しない。移行が必要なら旧形式コピー、新版読込、原本保全、未知版停止、確認復旧まで同じ区切りで実装する。専用試遊保存を通常正式保存へ無断で混ぜない。

## 工数と進捗管理

1人物・1敵・1イベント・1画面群を単位に、制作・修正・取り込み・画像確認を記録する。待機時間は分離し、作業時間が取れない場合は未計測と記載する。9-2の画面見本と最初の追加人物／敵／正式イベントの実績から見積りを更新する。

基準は `4H + 14E + NV + U + B + F + A + R + I`。Hは人物、Eは敵、Vはイベント、Nは追加イベント数、UはUI、Bは背景、Fは家具、Aは音、Rは見本修正、Iは統合作業。対象が重なる費用は二重加算しない。現時点では実績不足のため、納期・費用・1日の生成可能数を確定しない。

進捗は「未着手→設計→制作→接続→検証→正式採用」で管理する。予定の台帳は `plan9-content-inventory`、`plan9-ui-inventory`、`plan9-progress`、`plan9-completion-gate`。ファイル形式は9-1で現行検査ツールと合わせる。計画策定時に空の合格記録を作らない。

## 完了条件

### 2026-10-02 ローカル実装：戦闘定義のJSON読込（番号3・途中）

通常出撃をCombat/battle-preview.jsonの読込へ切り替えた。5人物／15スキル／5固有チェイン行動を参照IDから解決する。人物名・技名・消費資源・攻撃／部位倍率・回復人数／量・待機／詠唱時間・攻撃のチェイン可否を定義からUIと戦闘へ渡す。固定行動はHeroineのchainActionIdから独立に解決し、通常3コマンドへ追加しない。読み込めない場合はエラー表示と出撃停止で旧値に戻さず、セーブも書き換えない。

JSON全体の配列順を反転しても所有者と編成が変わらないこと、欠落／誤所有者／未知版／未対応効果／不正数値、2人を選ぶ回復、詠唱開始時の定義資源消費と発動後のチェイン可否、進行中の元データ変更からの隔離を検証した。既存仮値と40 seedで結果と時刻・乱数結果が一致する。パス・敵行動・詠唱発動へ過去のフルチェイン表示が残る問題も速度順モードで修正した。

検証結果：定義・チェイン852 assertions成功。Coreを独立コンパイルする検査を追加し、全C#44ファイルの検査に成功。Unityの実JsonUtility読込・画像寸法・人物／部位ID・表示行動者の検査をビルド前に追加し、975 assertionsとWindowsビルドに成功した。プレイヤーログでもCOMBAT_DEFINITIONS_PASSとBATTLE_STARTを確認。非表示ウィンドウの画面撮影は依然黒一色で、外観・クリック操作は未確認。

残項目：完全HeroineDef、13ジョブの正式資源ルール、任意編成、スキルの共通ルール台帳、固定行動の回復・状態効果・自動対象、効果量の汎用化、正式人物の固有データ。現在のstatusはplaceholderのみで、データ読込成功を正式バランス・美術完成と扱わない。詳細な先行交換形式は[データ契約](../data/contracts.md)に記録した。

### 2026-10-02 ローカル実装：2D戦闘表示基盤（番号2・途中）

BattleIllustrationViewをUnity戦闘へ接続した。大表示は演出イベントのActor、演出待ちではAvailableHeroで決め、人物カードの情報選択には連動しない。下部に5人のHP・資源・詠唱状態を維持し、回復イベントのHealingTargetsだけを回復対象として強調する。停止時は表示の経過を止め、スキップ時は既存の確定結果へ戻す。戦闘カメラは3Dを描画せず、箱庭・旧モデル確認の切替は残す。

Resources/Illustrations/battle-preview.jsonはschemaVersion=1の仮manifest。5人物のheroineIdで絵を対応させ、4部位のpartIdと正規化座標で選択枠を配置する。重複ID・欠落・NaN・範囲外・正式扱いの仮人物を拒否する。読込失敗は警告と未制作表示へ戻す。これは試作1敵用で、本番の4〜6部位や敵別背景・ポーズ差分・汎用対象ルールは番号3以降で拡張する。

hero-0だけ既存のスレイヤー2D方向性候補絵を仮表示する。暁の剣士の正式デザインとして確定したものではない。他4人を同じ絵で代用しない。敵・背景は単色と選択枠による仮表示で、美術完成とはしない。画像の縦横比を維持するため、Unityの非2冪画像リサイズとmipmapを無効化した。

検証：manifestの異常系を含むチェイン検証751 assertions、全C#43ファイルのコンパイル成功。Unity既存検証967 assertionsとWindowsビルドに成功し、game/Builds/playable/newASTER.exeを更新した。保存しない撮影モードで720p／1080p、回復演出の起動は確認したが、非表示ウィンドウとbatchmodeで撮影が黒一色となった。ログに実行例外はなく、実画面のレイアウト・クリック・回復対象・停止／スキップの目視検証は未完了。画像を受入証拠として扱わない。

次の順序：番号2の実画面・操作検証と修正→番号3の正式HeroineDef／SkillDef・固定行動JSONと対象／効果読込→番号4の新育成数値・ガチャチケット・保存移行。正式な人物イラストや背景の制作を、機能基盤の完了に含めない。

### 2026-10-02 ローカル実装：独立自動チェイン

Unityの速度順モードに、編成順の候補走査・独立固定行動・起点の戻り判定・追加一周を接続した。通常コマンドを追加受付せず、チェイン中は資源と論理時刻を変更しない。詠唱の起点補正を予約へ保持し、発動成功後だけ開始する。50%基本率、スキル+10%、最大2人の累積+5%を初期値として実装した。表示には補正とフルチェインの追加進捗を渡す。

人物行動はHeroineChainActionを明示注入する境界を追加した。ただし現在の5人はplaceholder定義（本体へ攻撃倍率0.6）で、正式なHeroineDef JSON読込・任意効果／自動対象ルール・正式人物の行動制作は未完了。回復・支援からのチェイン可否は未確定のため今回起動しない。行動不能は現行コアの戦闘不能のみで、スタン等の状態は未実装。旧非速度順モードは既存検証用に隔離し、正式仕様として採用しない。

tools/validate-automatic-chain.ps1で新規契約を検証し、tools/compile-unity-scripts.ps1で全C#を検査する。既存tools/validate-unity-core.ps1はEditor専用関数を含めて抽出する問題により利用不可だったため、これを全回帰合格とは記録しない。2D表示・覚醒／重複の新数値・ガチャ経済・保存移行は未着手。既存実行ファイルに自動で反映されたとはしない。

今回の実行結果：独立チェイン744 assertions、全C#41ファイルのコンパイル成功。UnityのPlayableBuild.ValidateAndBuildは既存検証967 assertionsとWindowsビルドに成功し、game/Builds/playable/newASTER.exeを更新した。これらは2D移行・正式人物・全状態異常・手動通し試遊の完了を意味しない。

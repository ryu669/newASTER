更新：2026-10-14。通常プレイの基準は25形態・22人物・13ジョブ（この更新日時点）。人数・人物／形態対応・現行データの正本は [人物台帳](../characters/index.json) と `ProductionContentPaths`。過去の計画10・計画12の段階別カタログを、通常プレイの最新版として上書きしない。

制作の入口は [ヒロイン追加方法](heroine-addition-guide.md)、ジョブ共通部分は [ジョブ別実装手順](job-implementation-guide.md)。直近の200人UI確認は [検証記録](heroine-200-ui-2026-10-13.txt)、保存・画像性能は [改善記録](runtime-stalls-2026-10-14.txt) を参照する。

## 次の実装

1. オーパーツ、13ジョブ、装備の木、重複強化の既存基準を新人物へ接続する。既存の数値調整を未実施へ戻さず、追加人物のスキル・特性との組合せを検証する。
2. 人物追加：全13ジョブが揃ったため、資料を指定された小ロットごとに追加する。200人超は将来の目標で、未制作人物を提供人数へ数えない。
3. 物語拡張：人物資料と既存世界・他人物の関係を確認し、章・詩・交流・回想・読書状態へ接続する。

具体的な新規着手はユーザーの指定範囲で進める。この文書の後続一覧だけで次の機能実装を自動開始しない。

## 人物ロットの完了条件

[追加方法](heroine-addition-guide.md)に従い、観察と創作の区別、人物／形態ID、3スキルと固有ジョブ、成長、共通方式の神器の木、専用画像20点を標準とする素材一式、3章30ページ・18詩・5交流、加入・編成・庭・ADV、保存互換と失敗再試行を揃える。画像比率と増員した一覧の最後の人物まで検証し、台帳をavailableへ変更する。

Core/DataとUnity C#、Windowsビルド、隔離したPlayer画面、原本と採用画像のSHA-256、本文・参照・ドキュメントリンクを確認する。別形態は人物関係を共有しても、成長・神器・読書進行を混同しない。基準値の最終バランスや物理操作の確認範囲は、結果と分けて記録する。

## 検証方針とGit運用

主要検証は `tools/validate-automatic-chain.ps1`、`tools/compile-unity-scripts.ps1`、人物資料・素材の検証、現行の `Plan12AprilBuild.ValidateAndBuild`、対象人物のPlayer検証。現在のビルド入口を更新する場合は `ProductionContentPaths` とこの案内も同時に更新する。

人数が増えた際は `tools/validate-heroine-scale-ui.ps1` で最低200人までの一覧・操作・保存を検証する。`-TargetPeople 205` のように目標を変えて境界も確認でき、既存人数が目標以上なら1人分の診断用人物を追加して増員操作を確認する。人物数と形態数は区別し、実行結果へ実際の数を記録する。

画像・保存処理を変えた際は `tools/validate-runtime-improvements-player.ps1 -Cases history,streaming,media` を使用する（PowerShellでは配列を渡す）。`streaming` は専用の320枚試験用AssetBundleが必要。`media` は実際のADV画像、閉じて開き直す操作、CG表示、回想の保存不変、戦闘用画像の先読みを検証する。

標準1920×1080で確認する。自動操作・表示画像・実聴の範囲を区別し、変更と無関係な完了済みキャラの画像確認は繰り返さない。実素材の容量負荷は5形態程度の追加ごとに既存の量産検証と比較する。人工の200人UIや320枚画像試験だけで、未制作200人分の実素材の合格とはしない。

新規作業ブランチはfetchした最新mainから作成し、PRの宛先はmain。計画間のブランチへマージを積み重ねない。継続中のブランチはその差分とmainとの関係を確認する。継続作業では既存PRの対象を確認し、既存の無関係なUnity設定変更は含めない。元動画、調査画像、ビルド、保存データはGitへ同梱しない。

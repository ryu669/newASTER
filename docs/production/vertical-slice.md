# 縦切りの範囲・検証データ・一周

更新：2026-10-02。状態：現行仕様。版はGit履歴で管理し、ファイル名に版番号を付けません。仕様整理のみで実装完了を意味しません。

目的は「巨神獣を倒すほど星と生活が育ち、ヒロインとの物語を読みたくなる」という完成体験を、量産前に1本で検証すること。本書は[制作ギャップ分析](../archive/production-gap-analysis-v0.2.md)のGate 1を実行する範囲であり、正式版の人数・内容を縮小確定するものではない。

## 範囲

| 分野 | 縦切りで作る内容 | 量産前に測ること |
| --- | --- | --- |
| 巨神獣 | 1体、本体＋4部位、Lv1〜50、大技、Lv45最強技 | 部位攻略の分かりやすさ、1戦の長さ |
| 戦闘 | 5人、互いに異なるジョブ、各3スキル、チェイン、属性・状態異常の最小セット | 行動選択と編成の意味 |
| 詩・物語 | 巨神獣24詩・3章、5人は対応詩と第1章を最低1本ずつ | 収集と読了のテンポ |
| 生活 | 箱庭1区画、家具3種以上、配置ヒロイン3枠以上 | 討伐→生活のつながり |
| 育成 | Lv、覚醒のUI、武器の樹1人分、オーパーツ1種、レリックハント1帯 | 強くなる実感と素材量 |
| UI | 万物の書4しおり、召喚、結果、物語本、セーブ | しおり／めくり／裏返しが直感的か |

縦切りで実装する人物・巨神獣の固有名、本文、見た目はTBD。既存の試作キャラクターを正式人物へ自動転用しない。

## 一周のプレイフロー

1. 新規開始後、万物の書の巨神獣しおりを開く。未討伐巨神獣の概要とLv1召喚を確認する。
2. ヒロインしおりで5人を編成し、武器・オーパーツ・スキルを確認する。
3. Lv1へ出撃する。部位、大技ゲージ、チェイン補正、ジョブ資源、詩取得を確認して勝利する。
4. 結果画面で、素材、テラフォーミング、巨神獣詩、対応するヒロイン詩を一括確定する。
5. 万物の書の物語しおりで、解放した章を本として読む。未取得詩は条件と進捗を表示する。
6. テラフォーミング到達で箱庭を開き、家具をクラフト・配置し、ヒロインを配置して会話・好感度イベントを読む。
7. 武器の樹とオーパーツを強化し、Lv10以上またはLv45以上へ再挑戦する。
8. Lv45で最強技を確認し、レリックハント報酬を得る。万物の書で詩・成長・討伐状態が保存されていることを確認する。

## 最初に決める初期ルール

以下は縦切りの検証値であり、正式版の固定値ではない。ただし実装前に空欄のままにせず、データ化して変更可能にする。

| ID | 項目 | 縦切りの決め方 | 変更の判断 |
| --- | --- | --- | --- |
| VS-01 | 戦闘の目標時間 | 初見3〜6分、既討伐の周回2〜4分を目標に測る | 判断がない／長すぎる場合は敵HP・行動間隔を調整 |
| VS-02 | 5人枠 | 5人必須で開始する | 所持不足時はテスト用貸出編成で補う。正式取得導線は別途決める |
| VS-03 | 属性・状態異常 | 属性3種、状態異常2種までを検証用に選ぶ | 名称・相性表は原作の未確認情報を流用せず新規定義 |
| VS-04 | 詩取得 | 未取得巨神獣詩を優先抽選し、結果画面で即時表示する | 24詩の初回読了に必要な勝利数を記録し調整 |
| VS-05 | チェイン | 基本率とターン補正をデータ化し、戦闘ログで全抽選を記録する | 最大5人が希少すぎる／頻繁すぎる場合に基本率だけを調整 |
| VS-06 | 報酬 | 勝利報酬を素材、テラフォーミング、詩、オーパーツ抽選に分解表示する | 何のために再戦するか不明なら報酬接続を見直す |
| VS-07 | 物語 | 巨神獣は3章すべて、ヒロインは各第1章を必ず読む導線を作る | 読む前に周回が苦痛なら確定済み詩数を維持し、取得頻度・取得条件を見直す |

## コンテンツの設計制約

### 巨神獣1体

4部位は、少なくとも次の役割を重複なく持つ。

| 部位役割 | 破壊しない場合 | 破壊した場合 |
| --- | --- | --- |
| 大技制御 | 大技ゲージが速く増える、または大技が強化される | 大技を遅延・弱化・中断する |
| 防御 | 本体へのダメージを減らす | 本体への有利な攻撃機会を作る |
| 妨害 | 味方に不利な状態・リソース妨害を行う | 妨害行動を停止する |
| 変化 | 本体の行動表または弱点を変える | 別の攻略ルートを開く |

どの部位も単なるHPの追加にしない。4部位をどの順で狙うか、無視して本体を削るかに選択が生じるよう、個体データで大技と行動を接続する。

### 5人のジョブ構成

縦切りの5枠は、攻撃、部位破壊、防御、回復／支援、状況操作の5種類の判断を必ず含む。具体的な人物とジョブはTBDだが、同じ行動を強さだけ変えて繰り返す5人にはしない。各スキルのデータには「敵本体／部位」「味方」「状態」「ジョブ資源」「チェイン」の少なくとも二つへの関与を持たせる。

### 物語・箱庭

- 巨神獣3章は、詩を8つずつ集めた時点で必ず読める。好感度や家具を要求しない。
- 対応ヒロイン詩は、戦闘中に聞いた巨神獣詩が帰還後の会話・本文にどう響くかを示す。単なる収集数にはしない。
- 箱庭には討伐結果から1つ以上の明確な変化（区画、家具、会話、ヒロイン動作）を必ず発生させる。
- 家具は少なくとも、座る、作業する、眺めるという異なる利用演出を持つ。好感度上昇を家具の放置報酬にしない。

## 技術実装の最小構成

1. 描画非依存の`BattleEngine`、`ProgressEngine`、`GachaEngine`を用意する。
2. 定義データをJSON等の外部データに置き、ID参照で戦闘・物語・報酬を接続する。
3. `battleId`と報酬済みIDを保存して、結果画面を開き直しても二重付与しない。
4. 乱数にはシードを渡し、戦闘ログに抽選種別・候補・結果を出す。
5. UIは万物の書の三層状態`bookmarkId / subjectId / faceId`を単一状態として管理する。
6. 画面・演出はエンジン結果を読むだけにし、HP・報酬・詩・解放フラグをUI側で直接変更しない。

## Gate 1の受入条件

[受入試験](acceptance.md)の戦闘・進行・表示・箱庭・ADV・契約ケースと品質ゲートを通し、一周のプレイログを記録する。本書は完成範囲と測定単位を定義し、試験期待値を別に複製しない。

## Gate 1後に初めて行うこと

縦切りのプレイ記録から、平均戦闘時間、部位ごとの選択率、チェイン長分布、詩の初回収集戦数、素材余剰／不足、物語読了率、箱庭滞在時間を集計する。その結果に基づき、13ジョブ、15巨神獣、ガチャ石配布、7系統の量産仕様へ進む。数値を実測せずに量産範囲を確定しない。

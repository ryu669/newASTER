# ヒロイン一覧・詳細・神器の改修

更新：2026-10-05。添付の木と人物画面の構成を参考にした本作独自の改修。参考画像のピクセルや原作UI素材は同梱しない。初期5人へ適用し、200人超の追加はジョブから段階的に進める方針を維持する。

## 一覧と詳細

名前と顔のカードを12人ずつ、4列×3行で表示。名前検索とジョブ絞り込みを組み合わせ、検索条件変更で最初のページへ戻る。所持済み・提供可能な人物だけを表示する。空結果を明示し、最後のページから次へ送らない。個人の順送りボタンを廃止し、安定heroineIdでカードから詳細を開く。256件の検索・絞り込み・22ページをCore機能検査する。200人の美術が存在するという意味ではない。

詳細は左に人物画・名前・次回出撃の能力と特性、右にレベル／覚醒／重複強化、3つのスキル、神器入口を配置。藍と金の人物面、象牙色の情報面、独自紋章アイコンを使う。能力は装備・遺物・特性を含め実際の戦闘計算から取得する。レベル欄クリックで育成、スキル行クリックで説明全文と現在／次Lvの比較を開く。特性アイコンはクリックで効果と解放条件を表示する。

## スキルLv1〜7

3枠を個別に保存。RC1の本作向け効果をLv1の基準として、倍率は `1 + 0.05 × (Lv−1)`。攻撃倍率・回復量・自己強化の効果量を最大130%へ伸ばす。資源消費、待機、詠唱、対象数、持続行動数、状態蓄積量、チェイン率、固定チェイン行動は変えない。自己強化の会心／防護は100%上限。元映像の観測Lv7を本作のLv1と同一であると主張せず、観測資料と本作の成長規則を区別する。

現Lv L→L+1の費用はネクタル60L。1枠Lv1→7で1,260、3枠で3,780。画面で現在／次Lvの効果と費用を提示し、確定前は無消費。保存失敗時は費用もLvも変更せず同じ取引を再試行。スロットを取引署名へ含め、同じIDで別スキルへ差し替えない。最大Lv7を超える強化・不正な配列・未所持は拒否する。旧保存の省略／nullはLv1として扱い、明示的な不正値を補修しない。

## 神器の木

各人13ノード（旧4ID＋各枝3段階の追加9ID）。旧root／alpha／beta／gammaと親条件を保持する。gammaは旧版どおりalpha・betaの両方を要求する。全枝を取得でき、枝選択で他枝を閉鎖しない。追加枝は人物固有の名前、効果、素材費用、位置を持ち、最終3枝にα／β／γを表示する。人物ごとに木の葉色と枝の形を変え、木の根・幹・葉・光と取得／選択／未解放ノードを描く。

各神器Lv1〜7。段階Lv Lで攻撃は `ノード基準攻撃＋2×(L−1)`、通常攻撃倍率は `ノード基準倍率＋0.03×(L−1)`。装備した1神器だけが次回出撃へ適用され、通常攻撃枠はその倍率にスキルLv倍率を掛ける。左欄に7段階の効果、必要素材・所持数・親条件を表示し、取得・強化・装備の確認を分離する。

強化素材はノードの取得素材を使い、基準取得量Cに対して `max(2,floor(C/3))×現Lv`。初期神器はその人物の最初の枝の素材を使う。取得済み神器だけを次のLvへ強化し、費用・段階・receiptを統合保存する。旧版で省略された神器Lvは1。Home内容版を更新し、RC1の装備・章既読・所持素材を保全する移行を用意した。

検証結果と現在の配布候補は別の `heroine-sanctuary-validation.json` に記録する。計画9 RC1の完了記録とパッケージは履歴として保持する。

# 計画6：万物の書・2D箱庭・ADVの詳細実装計画

更新：2026-10-03。状態：6-1〜6-10の機能ゲート完了。[完了記録](plan6-completion-gate.md)を参照。正式本文・美術・量産・人手受入れは計画7〜9へ引き継ぐ。[実装・検証記録](plan6-progress.md)を参照。計画5の機能ゲート完了後の実装順を定める。各項目の完了は検証記録を追加して判定する。

## 目的と完了範囲

万物の書から正式5人の育成・人物別装備の樹、解放された箱庭、詩による章、好感度イベントを開き、2D自由配置とADVを操作し、再起動後も同じ進行へ戻れる一周を完成させる。詩所持、章解放、本文読了、好感度、恋人状態、家具所持、配置、戦闘編成は独立した状態として扱う。

親仕様は[現行要求](../requirements/game.md)。詳細は[本の操作](../systems/book-navigation.md)、[箱庭](../systems/garden.md)、[ADV](../systems/adv.md)、[詩・好感度](../systems/collection-and-affection.md)、[育成・装備](../systems/progression.md)、[データ契約](../data/contracts.md)、[2D表示](../presentation/garden-and-adv.md)、[保存](../systems/save-and-migration.md)を適用する。実装都合で仕様を変更する場合は先に該当文書を改訂する。

計画6は機能と操作導線の完成を対象とする。正式本文・CG・人物絵・音の品質確認は計画7、量産・実戦経済は計画8〜9へ引き継ぐ。検証用本文と仮素材は用途を明示し、通常の正式物語として解放しない。3D制作を必須にせず、既存素材や旧保存を削除しない。

## 実装順と小区切り

順序は **6-1→6-2→6-3→6-4→6-5→6-6→6-7→6-8→6-9→6-10**。各区切りで利用可能な画面と異常系検証を追加し、コミットに対象・証拠・残作業を記録する。

### 6-1 定義・保存・診断の境界

- BookSubject、人物別WeaponTree、GardenLayout／FurnitureLayout、イベント条件、AdvScript／表示セットを内容版とIDで束ねる。未知schema、重複、欠落参照、範囲外、依存循環、正式パックのplaceholderを採用前に拒否する。
- 家具個体・配置・居住人物、取得ノード、好感度・恋人、解放／読了イベント、行既読、初回報酬receiptを別項目として統合保存へ追加する。現行型との対応表と欠落時の初期値を文書化してから保存版を決める。
- FormalCampaignJsonShapeとUnityFormalCampaignJsonを拡張する。新項目なし／明示null／空配列を区別して正規化し、未知将来版をbackup復旧より先に検出する。旧配列から正式好感度・装備・家具を推測付与しない。
- previewは複製snapshot、確定は共通revision・pending・receiptへ接続する。保存前の再検証、失敗時の元状態維持、同一操作IDの再試行を共通化する。

完了条件：計画4〜5の石・人物・詩・遺物・receiptを変えず旧正式保存を読み、新形式の往復・保存失敗・破損復旧・将来版停止をCoreと実Unity JSONで確認できる。検証パックは通常の正式保存と混用しない。

### 6-2 万物の書の操作を確定

- 分類内は明示pageOrderで並べ、重複orderを拒否する。先頭／末尾では方向ボタンを無効化し循環しない。0件なら対象なしとして説明を出し、裏返し・召喚・本文開始を無効化する。
- しおり変更は対象分類の先頭・概要面、対象変更は新対象・概要面、裏返しは同じ対象の別面。物語の文章ページを進めてもownerId／chapterIdを変えない。
- しおり飛来などの遷移は行先を一度固定し、途中入力をキューに積まない。スキップで一度だけ同期、閉じる操作で演出だけ中止する。再入場は規定の初期分類・概要面。
- 巨神獣／人物／庭／物語の目的別ページと戻り先を整理する。未解放は条件・進捗だけ表示し、本文・未見能力を漏らさない。

完了条件：0／1／複数対象、両端、分類切替、連打、演出スキップ・中止、読書往復を検証する。保留中の保存へ画面移動で別操作を割り込ませない。

### 6-3 正式人物別の装備の樹

- 初期ノードを下、成長方向を上にし、取得済みまで開花する。各人物の固有樹形とα／β／γ終端をデータで表す。約10武器／人物の量産目標と、処理を証明する小規模fixtureを分ける。
- 全親取得、同人物参照、非初期孤立・循環拒否、ノード別巨神獣素材費用を検査する。重複resourceIdの費用は合算し、不足・未定費用・overflowを拒否する。
- 確認に必要素材／所持、取得後能力・武器スキルを表示し、素材消費・取得・receiptを一括確定する。取得済みの再実行は無消費、取消も無消費。他枝を閉鎖しない。
- 武器装備枠と有効スキル選択の方針を先に定義し、対応済み能力だけ戦闘開始snapshotへ反映する。未対応効果は理由付き停止とし、チェイン率・速度を暗黙変更しない。

完了条件：正式5人の個別ページ、複数親、別枝、材料不足、再実行、保存再試行、装備前後の次戦闘差分を確認する。旧共通枝の数値を引き継がず、約50武器の正式制作は別の量産記録に残す。

### 6-4 家具クラフトと自由配置のCore

- 最初は1区画・家具3種で検証し、別庭も人物重複検証用に用意する。inventoryの所持とinstanceIdの配置を分離する。
- x／yは左上原点の正規化接地座標。drawTopLeft＝接地位置−drawAnchor×size01、footprintを描画矩形へ変換し、その全域がzone.bounds内にあることを検査する。
- 同ゾーンのfootprintの面積重複を拒否し、辺接触は許可する。絵の屋根・葉の重なりは衝突に含めない。初回の向きはorientation.defaultだけとする。
- 購入・クラフトは明示費用、配置／移動／撤去は個体単位で確認する。previewは未保存、取消は元配置、移動は同じ個体、撤去はinventoryを減らさない。確定時に再検証する。

完了条件：境界内外・辺接触・重複・未知庭／ゾーン／個体・二重配置・不正向き・NaN／無限値・非正サイズ・保存失敗を確認する。座標比較の精度方針を固定し、再読込で配置可否が変わらない。

### 6-5 2D箱庭・人物操作

- 背景、家具、人物、前景マスクを分離する。ゾーンorder→接地y→instanceIdの順で奥から描画し、人物にも同じ規則を適用する。
- 選択→preview→確定／取消、既配置の移動／撤去を画面へ接続する。家具操作領域と会話領域を分け、重なった候補を選べるようにする。
- 人物は戦闘編成とは別管理し、同一／別庭を通じて一人一配置。移動時は家具使用を解除する。名簿から隠れた人物にもアクセスできるようにする。
- idle→家具slot→対応action→会話→idleを一周させる。slot不足・非対応差分はidleへ戻し、人物違いの素材へ代替しない。演出中の状態は保存しない。

完了条件：人物3枠以上、家具奥の人物、複数候補、庭間移動、家具撤去中の使用解除、非対応素材の表示を確認する。未配置・家具不足・現実時間待機で物語を永久に止めない。

### 6-6 好感度・章・イベント条件

- ConditionExprを同一snapshotへ副作用なく評価する。all／any空配列、未知domain、欠落ownerId、負値、参照切れを拒否する。未定条件をalwaysへ置換しない。
- 詩所持→章解放と、章／読了イベント／好感度→イベント解放を接続する。章・イベント・恋人条件の循環を横断検査する。前提イベントは解放だけでは満たさず読了を要求する。
- 戦闘終了で詩と章が増えた場合は、その候補内でイベント条件も再評価し一括保存する。好感度変更・ADV完了時も同じ確定境界で再評価する。
- 正式5人各3好感度＋2恋人イベントのID枠を用意する。既存の関係を初対面に戻す本文を作らない。恋人移行は明示イベント完了で行い、数値到達だけで自動変更しない。

完了条件：詩・章・読了・好感度・恋人を個別検証し、本編章が好感度イベント必須にならない。交流費用・増分未定の定義は操作を停止する。本文未制作は解放状態と別に表示する。

### 6-7 ADV定義と実行器

- 開始前にcommandId／lineId一意性、非空本文、textId、背景・人物・衣装・slot・CG・speaker参照を検証する。最初の表示命令はbackground、endは末尾一つ。未知命令・end後命令を拒否する。
- background／actor／hideActor／cg／hideCg／line／sound／endを実行する。初回は選択肢・分岐・任意進行変更命令を追加しない。
- 同じ人物のactor更新は移動・差分変更。CGは一枚、hideActorsは状態を保持し、hideCgで復元する。表情は同衣装の通常差分へ戻し、未対応poseは用途付き仮表示を出す。
- UTF-8日本語本文を段階表示し、入力一回目は全文表示、次の入力で進む。全文表示後の送りで行既読を付け、途中表示は既読にしない。

完了条件：背景＋本文＋endの最小scene、二人以上、衣装・表情、CG往復、地の文、長文、欠落音の継続、欠落必須絵の正式受入れ拒否を確認する。

### 6-8 既読・中断・読了・回想

- 行既読はsceneId＋scriptVersion＋lineId。中断は保存済み既読を残すが章／イベントを読了にせず、再開はscene先頭。command位置と途中演出を永続化しない。
- endで章／イベント読了、明示恋人移行、初回報酬、関連解放、receiptを原子的に確定する。失敗時は同じ候補を再保存し、保存成功前に読了表示しない。
- 回想は完全な読み取り専用セッションにし、行既読追加・報酬・好感度・章／イベント進行を変更しない。回想入口は読了済みを対象とする。
- 開始ごとに背景・人物・CG・バックログ・autoを初期化する。本文定義改版時の既読扱いを明示し、旧lineIdを無条件に新本文へ適用しない。

完了条件：途中終了／再起動、end保存失敗／再送、初回と二回目、回想中の全命令、scriptVersion変更を検証する。強制終了では最後に保存した行までを保証範囲として記録する。

### 6-9 ADV操作と本への統合

- バックログ、文字速度、auto、既読skip、回想入口を専用操作へ整理する。skipは既読行だけ、最初の未読で停止し、途中の表示命令を飛ばさない。
- バックログ／ヘルプ／非アクティブ中は本文・auto・音声関連タイマーを止める。復帰は手動、経過分をまとめて進めない。バックログ閲覧で実行位置を巻き戻さない。
- 章・イベント一覧に未解放／未読／読了／本文未制作を区別し、詩進捗・条件・開始・回想を接続する。閉じた後は同じ本の対象へ戻る。
- 長文・ボタン・確認・保存エラー・戻る操作を720p／1080pへ整理する。計画4のアクティブ時間計測との画面対応を記録し、ADV演出時間を暗黙に報酬時間へ加算しない。

完了条件：最短／長文／バックログ多数、全速度、auto中断、既読skip境界、Esc、非アクティブ復帰、保存pendingの排他を確認する。

### 6-10 Windows通し受入れと引継ぎ

- 新規保存と計画5までの旧正式保存で、本→通常戦闘→詩／素材→章・庭→装備ノード→クラフト→自由配置→人物交流→イベント→ADV→回想→再戦→別プロセス再起動を通す。
- 別ケースで敗北／撤退、空分類、材料不足、配置取消、途中読書、保存失敗・再試行、backup復旧、将来版拒否を通す。進行変更ごとにreceiptと残高差分を確認する。
- Core回帰、Unity JSON／操作診断、Windowsビルド、実ファイル再起動を実施し、720p／1080pの画面証拠と結果を記録する。現在のCore 5,344・Unity 1,144項目は回帰基準で、件数増加自体を完了条件にしない。
- 自動診断と人手操作を別欄で記録し、自動操作を人手合格と呼ばない。人手で確認できない項目は未確認として計画7〜8に残す。

完了条件：6-1〜6-9の機能・異常系・通し保存が合格し、正式本文・美術・量産・人手未確認を明示したcompletion-gateを作成する。失敗ケース・必須保存検証が残る間は機能完了にしない。

# 計画8：実際の討伐供給と一周の経済

更新：2026-10-04。8-6の取引接続を実装し、実戦から得た残高で進む隔離診断を行う。人間の到達時間・30分の実アクティブ操作・Lv120の実到達は未測定。[通し検証](plan8-journey-validation.json)と[算術・抽選記録](plan8-economy-measurements.json)を別々に扱う。

## 採用した接続と修正

初期5人Lv1・ネクタル2940・結晶20、討伐のネクタル60＋10L・結晶min(5,1＋L/10)・石30＋2L、育成費用、ガチャの提供率・費用を変更していない。試遊の敵曲線・歌唱候補の変更は[8-4／8-5](plan8-adjustment.md)の専用内容版だけ。過去の報酬receiptと既得資産は再計算しない。

オリジナル試遊でもアクティブ秒と日替わり報酬を専用保存へ書く。通常版の未保存秒を試遊へ持ち込まないよう、入る前に保存し、出る前にも試遊側へ保存する。失敗時は元の秒と進行を保持して再試行する。診断capture以外の試遊で時計を進めるため、以前の「診断扱いだから全て計時しない」を試遊について修正した。

素材表示を昔の累計カウンタから正式Collection ledgerの残高へ修正した。装備・家具・交流・遺物の費用を支払った後の値を表示する。初期付与や報酬の水増しで不足を隠さない。

実機の10連保存でUnity JsonUtilityが任意のnull文字列を空文字列へ変える問題を確認し、素材結果の人物IDと未指定grantKindだけを読込時にnullへ戻した。未知種別・不正な人物ID・将来版の拒否は維持する。Unityのroundtrip検査と実機再起動で検証する。

ログインは当日の実日時で300石を受け取る。導入3000石は既存の任意・一度限りの操作IDを明示して呼ぶ。暗黙の初期石や、取得していない詩を補充していない。アクティブ秒60は保存失敗と再試行の専用診断で注入した値であり、実際に60秒操作したという記録でも30分報酬の実体験でもない。OS時計は変更しない。

100pt交換の独立通しケースでは、上記の続きから解放済みLv50を170周し、計235戦で追加90抽選分の石を確保した。100回の有償抽選、100pt→人物専用チケット、スレイヤー確定使用、交換保存失敗の無変更と同一操作再試行、使用後再起動・二重付与拒否が合格。最終は石74・ネクタル126860・結晶1073・素材12177・0pt・使用済みチケット0枚。チケット使用は有償回数を増やさず、欠片100を付与する。追加周回と交換の全残高は通し検証JSONへ記録した。

解放順を飛ばした旧24戦の診断は不採用にした。採用結果は毎戦の敵Lvを最高解放Lvと照合し、Lv2から順に進む65戦の履歴と追加交換履歴である。

## Lv120の算術と抽選の分布

5人をLv1→120へ育てる算術予算はネクタル77350、覚醒結晶400。初期分を引いて同じ敵だけを討伐する算術下限は、敵Lv1／10／50でネクタル1063／466／133勝、結晶380／190／76勝。解放・生存・途中の費用・実時間を除くため、実到達戦数や保証時間とは呼ばない。

20 seed×10000回、合計200000回の同じbanner抽選は★6合計3.0365%。近似95%標本区間は2.9613〜3.1117%で、設定3%を含む。これは分布の診断であり、この石や成果を保存へ配布していない。設定は合計3%・各人物0.6%・300石／3000石・100pt交換を維持し、抽選境界とチケットの無抽選保証はCore検査へ分ける。

再現：`tools/measure-plan8-battle.ps1 -EconomyStudy`、`tools/validate-plan8-story-player.ps1 -Journey -Telemetry`、交換は同じコマンドへ`-Exchange`を追加。表示証拠は`-Views progress,conditions,garden,events`と720p／1080pを使用する。負荷ベンチマークではない。

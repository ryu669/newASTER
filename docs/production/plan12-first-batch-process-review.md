2026-10-11。対象はアイオーン、アイアンメイデン、アヴァランチ、アナテマ、シヴァ。5人追加の作業は継続中で、ロット完了・公開済みとは判定しない。

## 原因

1. 全用途へ人物の共通説明を付けた。神器の指示に「NO people」と書きながら、その前後に成人女性の外観・服・ポーズを詳細に指定し、立ち絵も参照させた。用途別の指示を分離していなかった。
2. 既存の完成例を生成前の基準にしなかった。エクスカリパンやアイオーンの完成例は、人物の意匠を枝や葉へ反映した「木」である。今回の4点は人物の周囲にノードを置いた絵だった。
3. 生成後の内容審査より、ファイル数・透過・ハッシュ・取り込みを先に進めた。ハッシュ登録は採用審査の代わりにならない。
4. 絵の誤りをノード座標で吸収しようとした。座標を人物や飾りへ移して透過検査を通しても、正しい神器画像にはならない。この位置調整は取り消した。
5. 1形態を最後まで完成させる既存手順から外れ、追加4人を一括生成・接続した。最初の不具合が同じ用途の4点へ広がった。
6. 「生成済み」「自動操作成功」「目視確認済み」「キャラ完了」「通常プレイへ公開」を分ける記録と、昇格を止める仕組みが不足した。

## 改定した順序

1. 対象1形態の人物資料と採用判断を確定する。原作で観察した名称・効果、本作の数値変換、本作創作、未確認を区別する。創作した技・祝福名を原作の正式名として扱わない。
2. 用途別の仕様を作り、既存の合格例を参照する。画像ごとに主題・禁止事項・参照画像の役割・寸法・余白・ゲーム内での使い方を決める。
3. 立ち絵を生成・確認する。その後は人物、表情、戦闘、庭、神器、イベントCGの指示を分離する。全用途へ人物説明を一律に付けない。
4. 原画を用途単位で確認する。主題、同一人物性、身体・手・翼・武器、欠け、透過、CGの本文との一致を確認する。不採用と未確認は取り込まない。
5. 合格原画のハッシュと確認結果を保存し、初めてResourcesと採用一覧へ接続する。
6. データ・戦闘・保存の検証、Unity取り込み検証を行う。例外があればビルド成功ログがあっても不合格。
7. 既定起動1920×1080で、用途ごとの実画面とジョブ操作を確認する。原画が正しくても表情合成・家具接触・縦横比・文字・ノード操作が悪ければ表示側を修正する。
8. 1形態の制作記録を埋めて完了を判定する。画像ハッシュと表示経路が不変の確認は引き継ぐ。差し替えた画像と、その利用画面だけ再開する。
9. 合格した形態だけを通常プレイへ昇格し、索引・生成元・制作記録を同時更新する。次の形態へ進み、5形態が揃ってからロット全体の回帰・負荷・人物差を確認する。

## 神器画像の仕様

- 主題は根と幹から3枝へ伸びる神器の木。人物の身体・顔・肖像・SD・シルエットを入れない。
- 本人らしさは色、葉、花、金属、光輪や武器の装飾モチーフへ反映する。本人の立ち絵を背景にしない。
- 根1＋3枝×4段の13位置を確保する。枝の接続、ノード間の余白、文字と当たり判定を既存レイアウトと照合する。
- 1536×1024以上、3:2、実透過。生成した原画を無理に変形・切り貼りして合わせない。
- 生成には完成済みの木を構図参考として渡す。人物参照を渡す場合も色・意匠の参考に限定するより、色と装飾を文章で抜き出す方法を優先する。
- 審査順は「人物なしの木か → 根と3枝が読めるか → 13位置が収まるか → 透過・寸法 → 実画面」。後段の技術検査で前段の不合格を打ち消さない。

生成指示の基本形：

> 透明背景の横長ファンタジーRPG用神器の木。完成例の根・幹・3枝の構造と13ノード用の配置を参考にする。人物は一切描かない。根1つ、各枝4段。装飾の色と素材は対象神器の仕様に合わせる。顔、身体、人物のシルエット、肖像、文字、数字、UIは含めない。

実際の指示には対象神器の色・素材・装飾だけを追加する。女性の外観、年齢、衣装の着用状態、ポーズを追記しない。

## 追記：配色した基本の木から装飾を追加する案

以降のユーザー補足により、方針を「共通の木を配色して利用し、キャラごとに生成するのは透過装飾だけ」へ具体化した。木全体をキャラごとに再生成する方式は採らない。下記の完成PNG差し替え案は検討経緯として残し、現在の試作は木・装飾・ノード表示の3層に分けている。

2026-10-11の提案を踏まえ、量産ではこの二段階方式を推奨する。まず根・幹・3枝・13位置を確定した共通構図を用意し、キャラのイメージに合う配色の木を制作する。色だけの段階でも木として完成した見た目を成立させ、その後、葉・花・金属飾りなどを加えて個性を強める。

| 段階 | 制作内容 | 確認範囲 |
| --- | --- | --- |
| 基本の木 | 構図と13位置は固定。幹・葉・発光の配色を調整し、ノード枠の視認性を保つ。人物は描かない。 | 枝の接続、全13位置、背景との明暗差、文字と操作領域、透過・比率。 |
| 個別装飾 | 対象人物・神器のモチーフを、幹や枝の周辺の空き領域へ追加する。 | 装飾の用途・人物との対応、ノードや文字への干渉、差し替えた木の実画面。 |

配色候補はアイアンメイデンが銀灰・黒・赤い光、アヴァランチが深紅・墨色・金、アナテマが紺・青薔薇・金、シヴァが白・青・淡い桃。既存アイオーンの紫の木は維持する。これらは制作案であり、原作の正式な神器配色だと断定しない。全体を単色で染めると枝とノードの区別が弱くなるため、幹・葉・光を分け、ノードの視認性を優先する。

現状の描画はキャラごとの木PNG1枚と13個の操作ノードを重ねる方式。したがって、最初は同一寸法・同一配置の完成PNGを段階ごとに版管理する方法が変更量を抑えられる。共通幹＋配色＋透明な装飾レイヤーの合成も可能だが、現在は別レイヤーの項目・描画処理がない。複数キャラで装飾工程を試し、使い回せる装飾や追加頻度が分かってから対応を判断する。

画像編集で装飾を加える場合は、構図参考に合格済みの基本の木を渡し、幹・枝・13位置の保持を明示する。元PNGを直接上書きせず次版へ保存する。位置が変わった出力を座標変更で吸収せず、不合格として戻す。変更前の基本の木と、その確認記録は残す。

制作記録では「基本の木の確認」と「個別装飾の確認」を分ける。承認済みの共通構図や配色素材を使うことと、本人用の欠落を別用途画像で埋めることを区別する。色違いの基本の木を正式な第1段階とする場合はその旨を記録し、未制作の装飾を完成済みと書かない。ノードの効果や解放条件は装飾の段階に関係なく同じ仕様を維持する。

試行はアイアンメイデン1人で、配色した基本の木 → 原画審査 → 13ノードを重ねた実画面確認まで通す。その後に装飾を追加して、配置維持と作業量を比較する。成立した手順を残る3人へ展開し、既存の合格画像は作り直さない。

## 採用と完了の区別（運用）

[素材審査記録](plan12-first-batch-asset-review.json)では用途審査と実画面確認を別項目にする。今回の4点は `rejected`。未確認は `pending`、原画確認のみ済んだものは用途審査だけ `approved` とする。キャプチャ取得だけでは実画面を合格にしない。

`tools/validate-plan12-asset-reviews.py` とUnityの `Plan12AssetReviewGate` は、未確認・不採用・審査後にハッシュが変わった素材の採用／ロットビルドを拒否する。画像内容を自動で理解する仕組みではなく、実際の目視審査を省略させないための仕組み。今回の画像はこの検証で停止する状態が正しい。

再開順は、アイオーンの既存証跡を制作記録へ反映し、次にアイアンメイデンの木を1点制作・審査・接続・実画面確認まで通す。その工程が成立してから、アヴァランチ、アナテマ、シヴァへ適用する。確認済みの人物画像や戦闘テストは、関連変更がなければ繰り返さない。

## 2026-10-11：小装飾方式の4人への展開

上記の完成PNG案は検討履歴。現在は自然木・葉群・小装飾・花・操作ノードを分離した描画を実装している。アイアンメイデンの了承済み構成を基に、アヴァランチは扇と深紅、アナテマは青薔薇と青、シヴァは環飾りと淡い桃を採用した。アイオーンの合格済みの木は維持する。

- 小装飾は人物画像を参照せず、単独の透過画像として生成し、原画の画素を変更せず保管・取り込みする。
- 薄い葉群は全開放692箇所。花は根を除く12ノードの両脇24箇所。保存済み開放IDごとに連動させ、根のみでは葉も花も追加しない。
- 丸い装飾枠と既存のヒット領域を分け、木全体を下げて上部のルート見出しに葉を重ねない。
- 旧4枚の人物画像の木は不採用履歴を保持する。現行レビューは構成JSONと使用する全画像のハッシュを持つbundleに置き換え、部品の欠落・変更・未審査をPythonとUnity双方で拒否する。
- 確認はキャラ単位。既存の合格証跡を引き継ぎ、変更した木と未確認箇所を対象にする。原画審査、キャプチャ成功、目視合格、通常プレイ公開を別に記録する。

生成元・指示文は `game/art-source/first-batch-tree-ornaments-v1/generation.json`、描画は `LayeredWeaponTree.cs`、構成は `Resources/UI/WeaponTrees/<hero>.json`。人物設定は `docs/characters/` に追加した。公開判定は個別の制作記録を正とし、ビルド成功だけでは完了にしない。

## 2026-10-11：5人の完了・通常プレイへの追加

アイオーン、アイアンメイデン、アヴァランチ、アナテマ、シヴァの制作記録をキャラごとに完了した。上記の未接続・未確認は当時の課題であり、現行の残課題ではない。通常カタログは20形態・17人。各形態の `plan12-<hero>-form-record.json` と `plan12-first-batch-runtime-validation.json` を現在の判定とする。

5人合計105素材の原画用途と実画面を分けて承認し、旧不採用の木4枚は不採用履歴へ残した。公開ビルドは素材ハッシュと実画面審査済みハッシュの一致を要求する。撮影画像はローカルのQA出力として保持し、レビュー台帳へ撮影ファイルのハッシュを記録する。完了判定で生成成功を目視合格の代わりに使わない。

既定1920×1080で加入前後・編成・3技・ジョブ操作・庭・家具3姿勢・全章と交流の進行を確認した。旧15形態セーブから20形態への移行前後の全フィールド一致、5人の加入・保存・再読込、各人の召喚対象を実行版で確認。16→20形態の保存失敗時の原子性と重複のみのマスタリーは自動回帰で確認した。物理マウス操作は検証対象外で、操作メソッドの自動実行と実フレームの目視を別記録にした。

# 詳細仕様：成長・経済・万物の書UI v0.3（2D対応）

親仕様は[ゲーム要求仕様 v0.3](game-requirements-v2.md)。本書は進行、育成、ガチャ、万物の書、保存を定義する。

更新：2026-10-02。箱庭の配置・利用・交流・ADVは[2D箱庭・ADV詳細](spec-2d-garden-and-adv.md)、素材と受入れは[2D素材契約](spec-2d-assets-and-acceptance.md)を適用する。育成数値・ガチャ条件・詩／好感度の分離は維持する。今回は文書のみ。

## 1. テラフォーミング進行

勝利で得る`TerraformingGrant`を合計し、星全体の`terraformingXp`を増加させる。報酬は勝利確定時に一度だけ付与する。Lvが高いほど`TerraformingGrant`を増やすが、係数と上限はTBD。到達済みのしきい値は巻き戻さず、箱庭区画、家具レシピ、資源を解放する。

```text
TerraformMilestone { id, requiredXp, unlockType, unlockIds[] }
FurnitureDef { id, recipeId, placementRuleId, interactionSetId }
```

家具の配置・撤去は素材を失わせない方針を初期案とする。配置上限、グリッド、衝突、家具ごとの素材返却はTBD。ヒロインの家具利用は演出・交流入口であり、家具がないことでメイン物語や恋人イベントを閉鎖してはならない。

## 2. ヒロイン育成

### 2.1 Lv・覚醒・重複

| 状態 | 上限Lv | 遷移条件 |
| --- | ---: | --- |
| 通常 | 50 | 所持時の初期状態 |
| 覚醒1 | 80 | 覚醒素材・必要条件はTBD |
| 覚醒2 | 120 | 覚醒素材・必要条件はTBD |

全ヒロインの基本レアリティは★6。重複入手時は当該ヒロイン専用の重複強化へ変換し、ステータス・特性を改善する。最大強化後は汎用超過強化素材へ変換する。重複の必要数、上昇式、最大段階、変換量はTBD。変換前後を結果画面で必ず表示し、誤って所持ヒロインを削除しない。

### 2.2 装備の樹

```text
WeaponTreeDef { heroineId, nodes[] }
WeaponNode { id, parentIds[], tier, displayPosition, weaponId, cost, skillId?, statModifiers[] }
```

- 表現はヒロインを象徴する木。初期装備ノードを下部に置き、上へ伸ばす。取得済みノードまで花を咲かせる。
- 分岐位置と樹形はキャラクター固有。約10武器を配置し、終端はα／β／γ系の複数ルート。
- 解除は親ノード取得と巨神獣素材の消費を必須にする。各ノードの必要素材、能力、武器スキルを閲覧時に表示する。
- 取得済みノードの再払い戻し／再振りはTBD。決定前に、不可逆な枝選択を行わせない。

### 2.3 オーパーツ

```text
OopartDef { id, abilityId, fixedStatGrowthId, randomStatPoolId, levelCap: 120 }
OopartInstance { instanceId, defId, level, fixedStats, randomStats, directUpgradeState }
```

- 固有能力は`abilityId`、固定ステータスはLvに伴う決定済み成長、ランダムステータスは共通上限を持つ抽選値として別管理する。
- 同名再入手時は、同じランダムステータス種別ごとに`max(現在値, 新規値)`で上書きする。異なる種別の扱い、所持枠、装備枠はTBD。
- 各ランダム値が最大値の80%以上なら、素材を大量消費する直接強化を解放する。80%未満ではボタンを無効にし、理由と現在値／最大値を表示する。
- 直接強化は値を下げず、素材不足時に実行しない。素材・上昇量・上限判定の丸めはTBD。

### 2.4 レリックハント

レリックハントは別のスタミナ制コンテンツではなく、巨神獣をLv帯で再戦する周回ルールである。Lv10前後ごとの難度帯に報酬テーブルを持たせ、高Lvほど一回の戦闘で行うオーパーツ抽選回数を増加させる。Lv帯境界、抽選回数、確定ドロップ、上限、敗北時処理はTBD。スタミナ・日替わり・現実時間待機を要求しない。

## 3. キンダーガーデンとガチャ

```text
BannerDef { id, heroinePoolIds[], materialPoolIds[], oopartPoolIds[], heroineRate: 0.03,
            exchangeThreshold: 100 }
GachaState { bannerId, totalDrawCount, exchangeAvailableCount, history[] }
```

- 演出・入口の名称はキンダーガーデン。排出演出と結果確認をここで行う。
- ★6ヒロインの合計率は3%。同一バナーの対象ヒロインは均等に配分する。
- 残り97%は育成素材・オーパーツ等で構成する。内訳・レアリティ・バナー数・更新方針はTBD。提供割合画面と抽選テーブルを一つのデータから生成する。
- 100回でプレイヤーが対象ヒロインから一人を選び交換する。自動交換にしない。交換後のカウント、複数回到達時、持越し、対象外、期限はTBD。
- ガチャ石はログイン、プレイ時間、巨神獣討伐などで得る。スタミナは消費しない。ログイン周期・必要プレイ時間・配布量はTBDだが、画面に入手元と獲得量を明示する。

## 4. 万物の書：情報設計と遷移

万物の書は以下の三層を厳守する。UI実装は操作名と実データの階層を一致させる。

| 層 | ユーザー操作 | 変わるもの | 変わらないもの |
| --- | --- | --- | --- |
| 大分類 | **しおりを切替** | ページ群（巨神獣／ヒロイン／箱庭／物語等） | 選択中対象の同一性 |
| 対象 | **ページをめくる** | 同じ大分類内の対象ID | 大分類 |
| 情報面 | **ページを裏返す** | 同一対象の表裏（概要、部位、詩、報酬等） | 大分類と対象ID |
| 文章 | **本としてめくる** | 解放済みシナリオの本文ページ | 物語の所有者と章 |

### 4.1 画面要件

- しおり切替時は新分類のページ群が飛来し、選択しおりへ収まる演出を行う。
- ページめくりは前後対象へ移る。対象IDの変更をイベントとして発行し、情報面の状態は対象ごとの既定面へ戻すか維持するかをTBDとして明示する。
- 裏返しは同一`subjectId`のまま`faceId`のみを変える。対象取得、選択Lv、詩所持、部位の情報を別対象に混在させない。
- 物語は通常UIのカードではなく、本のページとして表示する。未読／既読、前後移動、バックログ、文章速度、オート、既読スキップ、回想を持つ。
- 未解放は存在・解放条件・進捗だけ表示し、本文、未公開の詩、未解放部位の詳細値を漏らさない。

### 4.2 最低限の大分類と情報面

| しおり | ページ対象 | 表 | 裏 |
| --- | --- | --- | --- |
| 巨神獣 | 巨神獣ID | 概要、選択Lv、召喚 | 部位、大技、詩、報酬 |
| ヒロイン | ヒロインID | 所持、Lv、編成 | スキル、装備の樹、詩、好感度イベント |
| 箱庭 | 箱庭区画ID | 区画、配置ヒロイン | 家具、クラフト、解放条件 |
| 物語 | 所有者ID＋章 | 解放済み章一覧 | 本文読了・関連詩進捗 |

表示順、フィルター、検索、既読マーク、音声有無はTBD。ただし、しおりで対象を切替えること、ページめくりで同一対象のタブを切替えることは禁止する。

## 5. 保存と原子性

保存状態を、定義データとプレイヤー進行に分離する。定義のID変更・削除はセーブ移行表なしに行わない。

```text
SaveV2 {
  version, playerId, mapProgress, defeatedColossusIds, highestClearedLevelByColossus,
  terraformingXp, unlockedMilestoneIds, furnitureInventory, furniturePlacements,
  heroineStates, weaponNodeIds, oopartInstances, collectedPoemIds,
  unlockedStoryIds, readStoryIds, affectionStates, gachaStates,
  claimedBattleRewardIds
}
```

- `claimedBattleRewardIds`で同じ勝利からの素材、詩、テラフォーミング、交流権、レリックハント報酬の二重確定を防ぐ。
- 章解放は詩追加と同じ保存単位、イベント解放は読了・好感度・報酬と同じ保存単位にする。
- 失敗時は書込み前の正常セーブを残し、再試行は同じ`battleId`を二重加算しない。

## 6. 受入試験

| ID | 確認 |
| --- | --- |
| P-01 | テラフォーミングしきい値を初回通過時だけ箱庭・レシピを解放する |
| P-02 | Lv50→覚醒1→Lv80→覚醒2→Lv120の上限以外へ成長できない |
| P-03 | 最大済みヒロインの重複を汎用超過素材へ変換し、本人を失わない |
| P-04 | 同名オーパーツの低値入手でランダム値が低下しない。80%未満では直接強化不可 |
| P-05 | ガチャ集計で★6合計3%、対象間の差がない。100回で任意選択交換が可能 |
| P-06 | しおり、めくり、裏返し、本読みでそれぞれ指定されたIDだけが変わる |
| P-07 | 同一`battleId`の結果保存を二回試行しても全報酬が一回分 |


## 7. 2D画面への接続

万物の書は2Dレイヤーとしてページ、しおり、情報、人物／敵絵、開花を描く。しおり飛来・めくり・裏返しは演出であり、状態遷移の完了を長いアニメーション待ちに依存させない。連続入力は遷移中に抑制し、スキップ時は確定済みのbookmarkId／subjectId／faceIdへ同期する。演出を理由に対象を二重変更しない。

装備の樹は根の初期装備から上へ伸び、親ノードから解放地点までを開花表示する。各人物の樹形・分岐位置・約10武器・複数終端を維持する。花の数や絵の見た目から取得状態を推測せず、保存されたnodeId集合を描く。素材不足／親未取得は理由表示、強化プレビュー取消で素材不変。

箱庭の2D配置・家具instance・人物配置、ADVの解放／読了／回想は[箱庭・ADV詳細](spec-2d-garden-and-adv.md)へ対応する。旧座標の移行表・保存版番号はローカル修正前に確定し、今回は保存データを変更しない。

キンダーガーデンの召喚絵・カットインは抽選後の表示。演出短縮・スキップ・再読で抽選回数、石、重複、100回交換進行を再処理しない。結果の確定と保存は既存の原子性規則に従う。

追加受入れでは、書の連打／短縮でID遷移が一度だけ、樹の絵とnodeIdが一致、配置取消で不変、召喚演出スキップで抽選不変を確認する。

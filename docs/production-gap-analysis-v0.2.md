# 制作ギャップ分析と確定順序 v0.2

対象は[ゲーム要求仕様 v0.2](game-requirements-v2.md)とその詳細仕様。本書は「何が未確定なら実装を始めると作り直しになるか」を洗い出し、制作の順序と各段階の完了条件を定める。ここでの提案は、ユーザー確定仕様と混同しない。

## 1. 結論：今不足しているもの

ゲームの魅力の柱（巨神獣戦、世界再生、ヒロイン交流、万物の書）は定まった。一方、完成ゲームへ進むためには、以下の順に空白を埋める必要がある。

| 優先 | 不足している決定 | 放置した場合の問題 | 今回の扱い |
| --- | --- | --- | --- |
| P0 | 戦闘の1ターン、ダメージ、勝敗、チェインの最終ルール | ジョブ・部位・装備を作っても強さを測れない | **先に詳細化** |
| P0 | 最初の縦切り（1巨神獣、5人、詩、箱庭、成長）の内容と完了条件 | 15体・多数の人物へ拡大して失敗を複製する | **先に詳細化** |
| P0 | データ形式、セーブ、乱数、報酬の原子性 | 報酬重複・移行不能・テスト不能になる | **先に詳細化** |
| P1 | 13ジョブの固有資源と役割 | 全員が似たスキルになり、編成の意味が薄くなる | 原作確認後に職別仕様化 |
| P1 | 15巨神獣の役割表・部位ギミック・報酬接続 | 数だけ増えて攻略と周回理由が重複する | テンプレートを先に作る |
| P1 | 育成数式、素材経済、ガチャ石の流量 | 早期にインフレまたは不足が起こる | 戦闘縦切りの実測後に調整 |
| P1 | 物語の7系統、人物加入、詩の対応表 | 詩の取得条件・交流・終盤導線を実装できない | 構造だけ先に固定、本文は後回し |
| P2 | UIの画面遷移、入力、アクセシビリティ、演出時間 | 良いルールでも読みにくく、周回が苦痛になる | 万物の書プロトタイプで検証 |
| P2 | 音、3D/2D演出、素材制作パイプライン | 仕様と素材負担が合わなくなる | 縦切りで制作コストを測る |
| P2 | 配布、年齢区分、参照作品との権利整理 | 完成後に公開・継続制作の妨げになる | 外部公開前に必須 |

## 2. 制作上の原則

1. **内容を量産する前に一周完成させる。** 15体、13ジョブ、7系統を並行実装しない。
2. **数値はデータ化し、コードへ埋めない。** 巨神獣Lv、部位HP、報酬、詩、ジョブ資源、チェイン補正を定義データから読む。
3. **ゲームの不確実性は表示する。** 予測不能な乱数は許容しても、チェイン補正、部位破壊条件、大技予兆、報酬条件を隠さない。
4. **周回は短縮できても価値は薄めない。** 初見は部位・詩・会話を味わい、既討伐はテンポよく素材・オーパーツを狙える設計にする。
5. **好感度と戦闘有利を結びすぎない。** 好きな人物を選んで進められ、交流しない人物も戦力として成立させる。
6. **ランダム成長は後退を生まない。** オーパーツ更新、重複、ガチャ、詩はいずれも既得の進行を奪わない。

## 3. 段階的な完成定義

### Gate 0：土台（実装を始められる状態）

- [ ] [縦切り仕様](vertical-slice-spec-v0.2.md)の未決項目を決定する。
- [ ] 定義データのスキーマとセーブ形式を固定し、ID命名規則を決める。
- [ ] 戦闘計算を描画から独立させ、同じシードで再現できるテストを作る。
- [ ] 実装基盤（Unity候補を含む）でWindowsビルド、ロード、セーブを一度確認する。

### Gate 1：遊べる縦切り

- [ ] 巨神獣1体、本体＋4部位、Lv1〜50、大技とLv45最強技を実装する。
- [ ] 異なるジョブ5人、各3スキル、チェイン、部位破壊、勝敗、報酬を一周させる。
- [ ] 巨神獣24詩、5人の対応詩、3章読了、好感度イベント1本、箱庭1区画を接続する。
- [ ] 武器の樹1人分、オーパーツ、重複変換、レリックハント1難度帯を実測する。
- [ ] 万物の書の三層UIを実装し、すべての解放条件を表示する。

Gate 1で確認するのは「楽しいか」「1戦の時間」「必要周回数」「ストーリーを読みたいと思えるか」「UIが迷わせないか」。量を増やす許可ではない。問題があればこの段階でルールを変える。

### Gate 2：量産可能な基盤

- [ ] 13ジョブの各固有ルールをジョブ別仕様とテストで確定する。
- [ ] 巨神獣15体の役割表を作り、部位ギミック・大技・最強技・報酬・詩の重複をレビューする。
- [ ] 7系統、ヒロイン加入、対応詩、テラフォーミング解放のデータを接続する。
- [ ] 育成・ガチャ・素材の100戦／100回抽選シミュレーションを行い、進行詰まりとインフレを検証する。

### Gate 3：製品完成

- [ ] 15巨神獣、各24詩、実装ヒロイン各18詩、好感度イベント3本＋恋人後2本を制作・校正する。
- [ ] 箱庭、家具、物語、回想、アクセシビリティ、音、演出、セーブ移行を完了する。
- [ ] 新規開始からエンディングまで、ネット接続なしで検証する。
- [ ] 権利・素材出典・公開形態を確認する。

## 4. 今後の検討順（決定台帳）

| 順番 | 決める項目 | 判断材料 | 完了の形 |
| ---: | --- | --- | --- |
| 1 | 戦闘コアの初期数式・ターン順・対象選択 | 縦切りのプレイテスト | 計算式とユニットテスト |
| 2 | チェイン補正の基本率と抽選方式 | 5人連鎖の頻度・偏り | シード固定の確率試験 |
| 3 | 1体目の巨神獣と5人のジョブ組合せ | 攻略の違いと物語の相性 | 縦切りコンテンツ表 |
| 4 | 詩の取得タイミングと1戦当たりの期待周回 | 読了までの時間 | 24詩・対応詩の取得表 |
| 5 | 報酬・テラフォーミング・育成の初期曲線 | 必要戦数・素材余り | シミュレーション結果 |
| 6 | 13ジョブの詳細 | 原作資料・戦闘テスト | 職別仕様とテスト |
| 7 | 15体と7系統の内容表 | ギミック・物語・報酬の重複監査 | 巨神獣台帳 |
| 8 | ガチャ・交換・石配布 | プレイヤーの入手感と不公平感 | 確率表・交換仕様・検証 |
| 9 | 本文・演出・音・箱庭の量産 | 制作時間・品質 | 素材台帳とレビュー |

## 5. 今回確定した次の作業

最初に実装するのは、全機能を薄く通す**縦切り**である。対象と完了条件は[縦切り仕様](vertical-slice-spec-v0.2.md)で定義する。13ジョブや15巨神獣を先に作ることはせず、縦切りの戦闘・物語・成長・UIが受入試験を通ってから拡張する。

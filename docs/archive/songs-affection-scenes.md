# 歌の収集・好感度・シーン・拠点交流

対象人物は[継承ヒロイン7人](inherited-heroines.md)。従来の6人想定を更新する。主人公は両作品を経験した観測者であるプレイヤー自身で確定（2026-09-20、ユーザー指定）。原作から続く関係を背景設定として保持するため、以下の好感度0「知り合い」や初対面会話を一律に適用しない。接続時点と人物資料に沿って初期会話を設定し、本作での交流進行と原作での関係を区別する。7人の好感度・個別シーンは、すべてこの同じプレイヤーとの関係として人物別に管理する。

2026-09-20。ユーザー指定により、以下を本制作の必須機能へ追加する。オフライン・個人利用の方針は維持する。本書はnewASTERの設計であり、参考2作品の個別ルールを再現・断定するものではない。これまでの「初勝利で記憶1ページ」「仲間の会話1本」を拡張し、該当部分は本書を優先する。現在のブラウザ試作には未実装。

## 1. ゲームの柱

1. **巨神／神獣に相当する敵の歌**を集め、その敵の過去・役目・最期を描く物語を開く。
2. **誓女／天使に相当するヒロインの歌**を集め、その人物の過去・願い・戦う理由を描く物語を開く。
3. **ヒロインを拠点に配置して交流**し、主人公との好感度を上げる。
4. **好感度と物語進行で個別シーンを解放**し、解放後は回想から見返せる。

戦闘・素材育成だけでなく、好きなヒロインを知り、関係を深めることを継続の目的にする。好感度は主人公と各ヒロインの関係を表し、部隊全体の数値にまとめない。

ここでの「歌」はユーザー指定の収集要素の呼称。初期実装では、題名・短い歌の一節・由来を持つ固有の「歌の欠片」として扱う。音源そのものの収集、歌唱、歌詞全文の制作は別の表現項目であり、欠片の収集数や物語の解放と混同しない。将来音源を付けられる参照欄を用意する。

## 2. 歌と好感度の役割を分ける

| 要素 | 分かること・変わること | 主な入手・成長 |
| --- | --- | --- |
| 敵の歌 | 敵自身の物語 | 対象の討伐、部位破壊、準備任務などの明示された実績 |
| ヒロインの歌 | その人物の物語 | 同行討伐、本人の拠点交流、特定の敵の物語への反応 |
| 好感度 | 主人公との距離、拠点での反応、個別シーン | 拠点会話、同行後の交流、個別シーンの初回読了 |
| 個別シーン | 二人の関係が進む出来事 | 好感度＋必要な本人の物語＋前のシーンの読了 |

ヒロインの歌で開く本編の物語には好感度を要求しない。好感度で開く個別シーンは本人の物語を前提にできるが、その物語からシーン読了を逆要求しない。条件の循環を作らない。

歌の欠片は武器強化や交換で消費しない。取得はコレクションへの登録で、物語を読むときも減らない。素材通貨・好感度・歌を同じ用途にしない。

## 3. 歌の収集と物語の解放

完成見本の着手値は、**敵1体につき欠片3つ・物語3章、ヒロイン1人につき欠片3つ・物語3章**。固有IDで所持管理し、同じ欠片の重複は進行を増やさない。欠片数1／2／3で順に3章を解放し、章を読む順は固定する。欠片の取得順そのものは固定しない。

| 方舟の歌の欠片 | 確定取得条件の案 |
| --- | --- |
| 方舟01：帰港の調べ | 方舟の初討伐 |
| 方舟02：失われた鐘 | 左翼を破壊して方舟に勝利 |
| 方舟03：残響 | 準備任務の初回成功 |

最初の翼破壊討伐で01と02を同時に取得可能。準備任務は本体討伐に必須ではないが、敵の歌を完成させたい場合に選ぶ理由になる。弱体化ONでも歌を得られ、弱体化なしの討伐は初回の歌集めの必須条件にしない。

| ヒロインの歌の欠片 | 各人共通の確定取得条件の案 |
| --- | --- |
| 本人01：旅の声 | 本人を編成して方舟に初めて勝利。戦闘不能でも同行実績として数える |
| 本人02：帰る場所 | 本人を拠点に配置し、固有の初回交流「出会いの続き」を読む |
| 本人03：呼応 | 方舟の物語第1章を読み、本人を拠点に配置して反応会話を読む |

戦闘に入れた3人は全員、該当する同行の欠片を得る。後に加入するヒロインも方舟への再挑戦で取得でき、取り逃し期限を設けない。全員を同時編成できなくても、順番に集められる。

初期は抽選ドロップにせず、未取得の歌について「どこで・誰を連れて・何をすれば入手できるか」を図鑑に表示する。方舟で仕組みが成立した後に他の敵へ条件を増やす。

## 4. 好感度

ヒロインごとに0～100。仮の呼称は0「知り合い」、10「親しみ」、30「信頼」、60「親愛」、100「深い絆」。好感度の上限は成長表示として使い、100まで上げないと主要物語を読めない設計にはしない。

| 行動 | 着手値 | 重複防止 |
| --- | ---: | --- |
| 拠点の固有会話を初めて読む | ＋5 | 会話IDごとに1回 |
| 同行して勝利後、拠点で「帰還の会話」をする | ＋5 | 戦闘ID×本人につき1回 |
| 個別シーンを初めて読む | ＋5 | シーンIDごとに1回 |
| 既読会話・回想の再生 | 0 | 何度でも閲覧可能 |

同行勝利ごとに本人の交流権を1つ得て、拠点で消費する案。複数回出撃しても未交流分は保存し、人数や配置枠の都合で消失させない。交流権はヒロイン別で、他の人物へ移せない。勝利報酬として保存するため、敗北・撤退の繰り返しでは増えない。

日付変更、現実時間の待機、ログイン日数を条件にしない。未配置や会わない期間による減少もない。会話の選択肢は反応の違いから始め、誤答による永久的なシーン封鎖は入れない。全員の物語と関係を1つのセーブで進められる非排他的な方式を初期案とする。

好感度を戦闘能力の必須強化にしない。好きなヒロインとの関係を進める目的を中心にし、交流しない人物を編成しても戦闘が成立する。

## 5. ヒロインのシーンシステム

ヒロイン別の物語と個別シーンを一覧にする。初期のシーン種別は、自己紹介・日常交流・人物の物語・親密さが進む個別イベント。会話、選択肢、表情、カメラ、背景、BGM、必要な挿絵を組み合わせられる再生器を作る。個別イベントの具体的な内容と表現は各シナリオの設計時に詰める。

| 個別シーン | 解放条件の案 |
| --- | --- |
| Scene 01：二人の時間 | 好感度10以上＋本人の歌の物語第1章読了 |
| Scene 02：打ち明ける願い | 好感度30以上＋本人の物語第2章読了＋Scene 01読了 |
| Scene 03：交わした約束 | 好感度60以上＋本人の物語第3章読了＋Scene 02読了 |

未解放の欄には不足条件と現在値を出す。たとえば「好感度18／30」「リネの物語第2章が未読」。条件達成時は通知し、戦闘や別の会話の最中に強制再生しない。

解放済み・読了済み・再生中を区別する。最後まで到達して読了を確定するまで、初回の好感度報酬を与えない。閉じた場合は章の最初から再開可能とし、長い章には区切りを設ける。初期は行単位の中断再開を必須にしない。

バックログ、文章速度、オート送り、既読スキップ、回想を用意する。回想では報酬、交流権、選択結果、進行フラグを書き換えない。既読スキップで終端へ到達した場合は通常の読了処理を通すが、二重報酬は発生させない。

## 6. 拠点への配置と交流

初期は固定カメラの拠点に**3枠：整備机・窓辺・休憩席**。加入済みのヒロインから配置し、同一人物の複数配置は禁止。配置は戦闘編成と独立させ、出撃メンバーを変えても拠点から勝手に外れない。

配置された人物は待機動作を行い、クリックすると、話す／歌と物語／個別シーン／配置変更を選べる。新しい会話や解放シーンがある人物には目印を出す。3枠を超える加入後も配置変更に費用や待ち時間を設けず、全員へ会えるようにする。

配置場所は待機動作と会話の雰囲気を変えるが、初期段階では好感度倍率・必須の家具・場所限定の進行ロックを付けない。歌や好感度条件を満たしても未配置なら、図鑑から「拠点に配置して会う」へ誘導する。

通常会話は、未読の歌への反応→未読の個別会話→帰還の交流→既読の日常会話を候補順に表示する。自動で交流権を使わず、好感度が増える選択肢には「交流権1・好感度＋5」を表示する。

拠点にいるだけで歌や好感度が増える放置タイマーは初期仕様に含めない。配置した少女と実際に交流することを中心にする。

## 7. 最初の完成見本で作る量

システムは3人全員に対応させる。最初の内容は段階的に揃えるが、ヒロインとの関係を後回しの追加機能にはしない。

| 種類 | 完成見本の内容 |
| --- | --- |
| 敵の歌 | 方舟の欠片3つと物語3章 |
| ヒロインの歌 | 3人それぞれ欠片1つ・物語第1章をまず完成させる。3つへの拡張が可能なデータ構造 |
| 拠点 | 3人を3枠に配置、固有の初回交流を各1本、帰還の交流 |
| 好感度 | 全員に0～100、入手・消費・保存・条件表示 |
| 個別シーン | 3人それぞれScene 01を各1本。回想と二重報酬防止 |

完成見本では未制作の第2・3章やScene 02・03を、条件を満たせば見られる完成コンテンツとして表示しない。「この版には未収録」と区別するか一覧から外す。未収録の歌の取得条件も有効化しない。

後の6人・3ボス規模では、各ヒロインの物語3章＋個別シーン3本、各敵の物語3章が目安となる。従来の「会話1本」案より制作量が増えるので、モデル数だけでなく、本文・表情・撮影・挿絵・音の制作量を段階ごとに測る。

従来の完成見本8～15分は、今回追加した全交流コンテンツの読了時間には適用しない。最初の討伐から1人のシーン解放までを導入の測定単位にし、全員分の収集・閲覧は別計測する。

## 8. データと保存

定義データ：`SongFragment(id, ownerType, ownerId, title, verse, sourceCondition, audioId?)`、`StoryChapter(id, ownerId, requiredFragmentCount, previousChapterId?, sceneId)`、`HeroineScene(id, heroineId, requiredAffection, requiredReadIds, scriptId)`、`BaseSlot(id, poseAnchor)`。定義とプレイヤーの取得状態を分ける。

保存に以下を追加する。

- `collectedSongIds`：取得済みの固有欠片ID。数量加算ではなく集合。
- `heroineAffection`：人物ID→0～100。
- `baseAssignments`：拠点枠ID→人物IDまたは空。戦闘formationとは別。
- `pendingHomecomingCredits`：人物ID→未使用の交流権数。
- `unlockedStoryIds / readStoryIds / unlockedSceneIds / readSceneIds / readDialogueIds`。
- `claimedFirstReadRewardIds`：初回読了報酬を処理済みのID。

歌・交流権・素材は勝利報酬と同じ保存単位で確定し、戦闘IDで重複を防ぐ。拠点会話の読了は、読了フラグ・好感度・歌の取得・交流権消費・新しいシーン解放を一括保存する。保存再試行は同じ結果を再保存し、計算し直して二重加算しない。

拠点配置も変更時に保存する。セーブ移行では既存の物語解放を失わせない。ブラウザ試作の`memory=true`は製品へ自動取込しない方針を維持する。製品の旧版を移行する場合だけ、旧記憶IDと新しい物語IDの対応を明記する。

## 9. 実装と受入れの順番

1. 固有歌の所持、章の解放、個人好感度、シーン条件を描画非依存の進行ロジックで作る。
2. テキストと仮アイコンで、報酬→歌の章解放→読了→交流→シーン解放→回想を一周させる。
3. 拠点の3D配置・待機・クリックを接続し、人物ごとの表情とカメラを付ける。
4. 各人の本文と演出を仕上げ、戦闘・育成と一緒に新規開始から検証する。

必須試験：歌の重複取得、複数同時取得、主人公との好感度の人物別管理、解放条件の循環がないこと、未配置人物への交流権保持、3枠を入れ替えて全員に会えること、二重配置の拒否、会話中断時の未読、回想での進行不変、初回読了の二重報酬防止、保存失敗時の再試行、再起動後の配置・好感度・歌・回想の保持。

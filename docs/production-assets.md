# 3D素材の着手仕様

> 2026-09-22整理：正式版の範囲・受入条件は[要件定義](requirements.md)を参照。本書の旧人物・旧人数・仮数値は検討履歴／試作仕様であり、正式版の確定事項へ自動転用しない。

人物選定は[継承ヒロイン7人](inherited-heroines.md)へ更新。自作の仮モデルから進める方法は維持し、外見の設計は原作の人物資料に基づく。以下のセラ等の外観・武器・色指定は旧試作の技術検証用で、継承人物のモデル仕様には使わない。

[歌・好感度・シーン・拠点交流](songs-affection-scenes.md)の追加に伴い、ヒロイン配置用3枠、拠点待機・交流動作、会話用表情、シーン用カメラ、歌の図鑑・好感度・回想UIを必須素材に含める。初回完成見本では3人の個別シーン各1本を制作し、必要な挿絵と演出はシーン台本ごとに台帳へ追加する。

2026-09-20。独自の仮モデルから無料で段階的に制作する。購入・外注・原作素材の抽出を前提にしない。[本制作着手仕様](production-ready-spec.md)に従い、セラ1人の制作工程を先に通す。

## 1. 完成段階を分ける

| 段階 | 作るもの | 判定 |
| --- | --- | --- |
| A：形と動き | 体、頭、髪、衣装、翼、武器の単純形状、基本の骨格、単色材質 | 3方向から見て人物と役割が分かり、飛行・技・帰還が動く |
| B：人物として読む | 顔の形、目、髪の輪郭、手、衣装の大きな分割、表情 | 顔への接写で形が破綻せず、3人の違いが分かる |
| C：完成見本 | テクスチャ、陰影、輪郭、動作の調整、技エフェクト | 実際のカメラと光で見てユーザーが採用できる |

手続き生成した単純形状だけで段階Cに到達したとは扱わない。設定画・モデル・動作を順に修正し、人物1人のB段階を見る前に全員分の細部を量産しない。

## 2. 3人の外観指示

| 人物 | 仮の外観 | 武器・動き |
| --- | --- | --- |
| セラ／防御 | 青緑と灰白。肩までの髪、短い上着、左右に張る翼。胸元と肩に直線的な形 | 前腕の盾状装具。仲間の前へ出て両腕を開き、防壁を展開 |
| リネ／支援 | 淡い紫と白。丸みのある髪・襟、短い裾。セラより柔らかい輪郭 | 小さな環状の装具。上体を起こし、手元から仲間へ光を渡す |
| アシュ／攻撃 | 琥珀と暗紺。短い髪、細い胴、後ろへ流れる翼 | 長い槍状の武器。体を傾けて突進し、敵を抜けて旋回帰還 |

輪郭と色による読み分けを優先。初期は長いスカート・複雑な髪物理を避け、ボーンの簡単な追従で表現する。裸の素体をプレイ画面の完成モデルとして使わない。

## 3. ファイルとモデルの共通条件

- 元データは`art-source/`の`.blend`、Unity取り込み用は`game/Assets/Art/`へ書き出す`.fbx`とテクスチャ。`.blend`の自動取り込みだけに依存しない。
- 単位はメートル。Unity取り込み後に足元を原点、Y上・Z前として身長約1.65mになり、負のスケールがないことを確認する。
- 人体は共有しやすい骨格、翼と武器は追加のボーン／取り付け点。Humanoidによる動作の再利用を候補とし、Avatarと翼の動作を実機確認する。[Unityのリターゲット説明](https://docs.unity3d.com/6000.0/Documentation/Manual/Retargeting.html)。
- 頭・胸・両手・翼根・武器・カメラ用のアンカーを命名して固定。武器の原点を握る位置に合わせる。
- 適用済み変形、材質名、法線、UV、テクスチャ参照、アニメーションクリップを1人目で確認。書き出し設定も元データとともに残す。
- 仮の上限目安は1人30,000三角形・材質4個・主テクスチャ2048px。ボスは150,000三角形・材質8個から測定。これらは性能保証ではなく、初期の増えすぎ防止用の枠。
- 透明な髪を大量に重ねず、最初は不透明な形で輪郭を作る。大きな布・髪・翼の物理シミュレーションは後から必要性を判断。

## 4. 動作の最小一覧

| クリップ | 目安 | 条件 |
| --- | --- | --- |
| flight_idle | 2～3秒ループ | 翼の動きと上下動。位置移動は制御側で行う |
| approach / return | 各0.4～0.8秒 | 前傾・旋回姿勢。経路はターゲットのアンカーで決める |
| normal_attack | 0.5～0.8秒 | 通常カメラで何をしたか分かる |
| skill | 1～1.5秒 | 予備動作・見せ場・終了を区別。効果適用は1回 |
| hurt | 0.2～0.4秒 | 浮遊姿勢を壊さず、次の待機へ復帰 |
| down | 0.8～1秒＋保持 | HP0を表現。画面外へ落下し続けない |
| victory | 1.5～2秒 | 再戦では短縮できる |

初期の表情は通常・集中・被弾・安堵の4つ。目と口の形を切り替える方式から始め、全編音声や口パクは必要条件にしない。通常3人連携3～5秒、短縮1～2秒に収めるため、全員の接近・帰還を毎回独立した長い映像にしない。

## 5. 方舟・背景・拠点

方舟は本体、左翼、右翼、核、砲口に分ける。初回ゲーム上の破壊対象は左翼だけ。外観上の部品数と攻撃対象数を区別し、選べる部位を輪郭表示する。

本体・左翼の命中位置、味方の待機点3つ、接近経路、帰還経路、4種類のカメラ基準点を持つ。左翼破壊後は翼片の短い落下と欠損形状を表示し、破壊済み部位へ次の技が飛ばないことを確認する。

空域は空の背景、雲の層、遠い浮遊遺構、近い残骸で距離を作る。全周の巨大な地形は作らない。拠点は整備机、記憶帳、窓、少女の待機位置の1画面から始める。

## 6. 素材台帳と受入れ

完成見本に必要な台帳の初期行：人物3、武器3、方舟1（破壊状態込み）、空域1、拠点1、防御／回復／攻撃エフェクト各1、大技1、翼破壊1、基本UI、戦闘BGM1・拠点BGM1・基本SE。初期の音は自作の仮音から始め、常時無音のまま完成扱いにしない。

各素材にはID、元ファイル、書出し先、作成方法、段階A/B/C、未解決点を記録する。「作成済み」は未作成の予定行へ付けない。

受入れはUnity内の実際の光とカメラで行う。顔の接写、3人が並ぶ通常画面、翼と武器の交差、左翼破壊後、短縮演出、一時停止からの復帰を確認する。静止画だけの良し悪しで採用を決めない。

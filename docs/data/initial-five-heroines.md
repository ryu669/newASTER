- スレイヤー：単体物理200%、自己3ターン強化、単体物理280%・長い待機。第2技は回復ではない。
- アイコノクラスト：単体物理170%とWT効果、単体魔法320%と自身最大HP10%の反動、全体物理240%とスタン値45。全技を物理扱いにしない。
- アンダーマイン：単体物理200%と火傷・スタン・反動、自己再生140%・物理防護40%・強制標的など4ターン、単体物理280%と最大9チャージ消費。単純な味方全体ガードで代用しない。
- エキドナ：範囲内への物理240/300/360%。全3技で詠唱、やや短い／普通／やや長い。発動後待機は短い。闇属性だから魔法攻撃、ブラスターだから第2技だけ詠唱、と解釈しない。
- エクスカリパン：単体物理126%、単体物理163%と自己攻撃強化・基礎攻撃力70%自己回復、全体物理240%と火傷・特殊兵器時強化。自己回復の基準を現在の強化済み攻撃へ勝手に変えない。

詳細な倍率・効果量・対象・持続・待機／詠唱区分はJSONを確認値の定義元にする。これはLv7の観測であり、Lv1〜6や将来の調整数値ではない。

## 資料形式の意味とTBD

`status=reference-only`、`statContext=equipment-adjusted-snapshot` を必須とする。未読上限は `damageCap=-1`。`recovery=unspecified` は説明に追加待機の記載がないことであり、実測100%確定ではない。詠唱区分を150%等へ根拠なく変換しない。`turns=0` はターン持続の記載なし／一回の攻撃時・行動後効果を記録する値で、状態異常の持続0ターンを意味しない。状態値は発症確率ではない。

WT+30の適用対象・単位は未解決として `target=unresolved` を明示する。チャージ9個の効果倍率、再生時点、ターン消費、強制標的の全体攻撃との関係、範囲攻撃と部位対応、状態発症閾値、特殊兵器条件・倍率の合成順はTBD。動画全編を検証済みとは扱わない。特性・ジョブ資源・武器・祝福・装備補正の網羅は次の確認対象。

## 次の実装順と受入れ条件

実装済みの先行共通処理：成功した攻撃の後の基礎攻撃割合自己回復・最大HP割合自己反動。通常発動と詠唱発動へ接続し、資料の70%回復・10%反動を検証用定義でテストした。ただしエクスカリパンの攻撃に付随する強化や出血、アイコノクラストの魔法判定等は未実装のため、人物ごとの技全体を正式実装済みとはしない。既存仮スキルの配布JSONへ名前だけ付けて流用しない。

持続する自己攻撃強化・再生・物理防護・会心率／威力・強制標的を共通処理へ接続した。攻撃後の強化と全3枠の詠唱攻撃にも対応する。資料の15%/3ターン、140%/4ターン、40%/4ターン相当を検証用定義で試験する。ただし消費単位を本人コマンド回数にしたのはnewASTERの先行方針。状態異常、範囲／全体対象、魔法判定、資源・特殊兵器・チャージ・特性などは未接続で、元の技全体を完成扱いにしない。

1. 動画の実行場面から資源消費／獲得、WT・詠唱、対象範囲、特性を追加確認する。未確認はTBDのまま分離する。
2. 物理／魔法、複数効果、自己反動、持続強化、再生・防護・強制標的、状態値蓄積を共通解決器へ実装し、処理順と端数をテストする。
3. ユーザー委任の調整範囲でジョブ基準＋人物補正、待機／詠唱の試遊値を設計する。確認値とnewASTER調整値を別に記録する。人物固有チェイン行動はHeroineDef側で定義し、通常技の代用にしない。
4. 正式人物IDをセーブ・編成・イラスト対応へ接続し、旧仮5人のデータを無断で別人物へ転用しない。旧セーブ移行は計画4と整合する。
5. 15通常技と5固有行動の実行・UI・イベント・詠唱・資源を検証して正式編成へ切り替える。それまで今の試遊戦闘は旧仮5人であると明示する。

資料登録と読込検証だけで計画3を完了扱いにしない。計画3の全完了条件は[実装計画](../production/implementation-plan.md)に従う。

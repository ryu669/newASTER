## 資料の使い分け

第1ロットの5人は専用画像・本文・戦闘・保存・既定解像度での表示確認を完了し、通常プレイへ追加済み。完了済みの人物は変更の影響がある用途だけ再確認する。

- このフォルダ：本作の採用設定、執筆基準、収録章・交流ID。物語制作の入口。
- [参考観察](../references/README.md)：原作の観察、時刻、未確認範囲。本作設定を自動で上書きしない。
- [物語本文](../story-text/README.txt)：読み通し・推敲用の本文。実行JSONが現在の収録内容。
- [追加手順](../production/heroine-addition-guide.md)：人物追加と検証。
- [今回の動画照合と採用判断](video-decisions-2026-10-10.md)：初期5人の性格差・既存本文との接続。

口調の例は本作の収録台詞または独自の執筆方針。全音声の書き起こし済みとは扱わない。原作の未確認項目を埋める場合は指定動画を確認し、時刻と本作での採用判断を別々に追記する。

## 主人公の呼称

主人公は「指揮官」を基本とする。「指揮官さん」「指揮官くん」などの敬称や、ヒロインの性格・口調による特例を許可する。人物ごとの基本呼称と特例は各人物資料に明記し、別衣装でも継続する。地の文の「あなた」は呼びかけとは区別する。既存の収録台詞例は引用として保存し、今後の台本改稿で文脈に合わせて反映する。

## 共通の制作基準

人物IDと形態IDを区別する。特性はジョブ特性・キャラ特性・交流特性の3分類、基準は2＋3＋3、全員7〜8枠。27種類は交流タグ。タグを性格の代用にしない。好感度・恋人関係は人物単位で維持する。成人としての本作設定を維持し、別衣装で年齢や関係をリセットしない。

`index.json` は実装済み全形態との対応表。`python tools/validate-character-docs.py` で網羅と本文参照を検証する。

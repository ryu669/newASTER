# 詳細仕様：2D素材契約・品質・受入れ v0.1

更新：2026-10-02。親仕様は[2D要件](2d-illustration-spec.md)。素材量産・Unity取込み・性能確認は後続ローカル作業。ここでの解像度は着手値であり最終値ではない。

## 1. 共通契約

全素材はオリジナル。既存作品の画像・文章・モデル・抽出データを流用しない。作者、制作日、元データ、利用条件、素材ID、用途、採用状態を台帳へ記録する。生成絵や過去比較絵も自動的に正式採用しない。

```text
ArtAsset { assetId, ownerId?, usage, sourcePath, exportPath, author,
           createdDate, provenance, rightsNote, status,
           width, height, colorSpace, alphaMode, pivot, canvasGroupId }
status = study | placeholder | review | accepted | retired
```

`assetId`は不変とし、パスや日本語表示名と分離する。欠番・未採用素材を公開情報のように表示しない。人物や巨神獣のゲームIDは素材IDへ明示対応する。画像差替でゲーム進行のIDを変えない。

## 2. 納品単位

| 用途 | 着手サイズ・形式 | 統一条件 |
| --- | --- | --- |
| 背景・CG | 1920×1080以上、不透明PNG、sRGB | 16:9の安全域、文字なし |
| 立ち絵 | 1600×2400目安、RGBA PNG | 全身・武器を収め、衣装間の接地と人物位置を揃える |
| 戦闘ポーズ | 1024〜2048角目安、RGBA PNG | 同じ人物、動作の基準点、武器・翼を欠かさない |
| 顔・表情 | 用途別TBD、RGBA PNG | 同じキャンバス・顔位置・輪郭、CGとの人物一致 |
| 巨神獣 | 本体＋4〜6部位、サイズTBD、RGBA PNG | 個体内キャンバス／pivot／描画順、破壊前後位置 |
| 家具・SD | サイズTBD、RGBA PNG | 接地anchor、利用スロット、前後マスク |
| UI・効果 | サイズTBD、必要なら9-slice／連番 | 日本語文字は別表示、色だけに状態を依存させない |

RGBAは書き出し工程で縁の白／黒にじみを確認する。明示した消失差分以外で透明画像を正常素材として採用しない。大きいCGを多枚数で読み込むだけの方式は避け、ロード方式とメモリ予算を測定後に固定する。

レイヤーを保持した編集元とPNG書き出しを別管理。取り込み先案は`game/unity/Assets/Game/Art/Illustrations/`、編集元は`game/art-source/2d/`。ファイル名はASCIIの安定IDと用途・版を使う。Git LFS、最大画像サイズ、圧縮、アトラス、読込み方式はTBD。

## 3. 差分整合性

差分セットは`canvasGroupId`で管理し、サイズ、pivot、基準人物、衣装、画風を照合する。表情差分だけなら顔以外が変化しないこと。立ち／座り／戦闘でキャンバスを分ける場合は、各セットのanchorを明記する。

巨神獣の破壊絵は部位IDと一致し、隣の部位を誤って消さない。本体側に同じ部位を描き込んで二重表示しない。必要な破断面や本体差分は個体セットに追加し、制作時に列挙する。

人物の顔、衣装、武器、左右の非対称意匠を全用途で確認する。画像反転で意匠が逆になった場合は専用差分を制作する。未採用絵を色替えして別人物数に数えない。

## 4. 読込・欠落・画面設定

ロード時はmanifestに対してID重複、必須画像、部位数、差分対応、画像寸法、pivot範囲、描画順、選択領域を検証する。必須画像欠落は開発時に警告＋用途名付き代替を表示し、正式受入れでは不合格とする。任意表情は同一人物・衣装の通常表情へ戻せる。欠落でHPや報酬を変更しない。

設定は文字サイズ、表示モード、BGM／SE、揺れ軽減、フラッシュ軽減、演出短縮。設定変更で再抽選・行動再計算しない。読み込み中に入力を受けた場合は未準備の操作を無効化して理由を表示し、コマンドを二重送信しない。

## 5. 品質ゲートと確認記録

| ゲート | 必要な成果物 | 合格条件 |
| --- | --- | --- |
| Q1：人物1人 | 立ち絵・表情・戦闘・カットイン | 顔・手・武器・衣装・透過縁を1080p実画面で確認 |
| Q2：敵1体 | 本体＋4部位以上・破壊差分・背景 | 巨大さ、各部位選択、破壊後の輪郭が明確 |
| Q3：縦切り画面 | 5人戦闘・箱庭・ADV・回想 | UI重なり・差分位置・720pの操作可読性が成立 |
| Q4：動作一致 | 通常／短縮／スキップ／停止復帰 | 同じ入力と種でHP・詩・報酬一致 |
| Q5：Windows | 実行ファイル・保存／復旧・ログ | オフライン主要フローと再起動を確認 |
| Q6：量産判断 | 1人・1敵・1イベントの実工数 | 15体と採用人物分の見積りを更新 |

性能目標は手元PCの1080p・60fps。代表戦闘の通常区間の95%が16.7ms以下を目標に測定し、ロード・カットイン・箱庭・ADVのピークメモリと読込を別記録する。機材、ビルドID、場面、画像設定、測定区間、結果、既知問題を記録する。メモリ／読込時間の合否数値はTBDで、実測前に保証しない。

本書の作成でQ1〜Q6が合格したとは扱わない。今回の確認は文書整合性と参照リンクのみ。

# 正式版着手パッケージ v0.3（2D版）

更新：2026-10-02。親は[現行要求](game-requirements-v2.md)。[実装契約](spec-implementation-contracts.md)と2D詳細を適用し、旧3D制作・旧ブラウザ照合の開始条件を置換する。今回は文書のみ、実装は後日ローカルで行う。

## 1. 開始条件と現状

既存Unityは6000.6.3f1、戦闘・進行・表示の実装がある。過去Windowsビルドの記録と2D版のビルド検証は区別する。3D表示の置換、正式人物・固有行動・素材量産は未完了。古いブラウザゲームは廃棄対象で、保存・テスト・fixture照合を要求しない。今回は削除・復元を行わない。

## 2. ローカル実装の順序

1. 使用するUnity版と依存、現在のセーブ版を記録する。
2. チェインと終了／演出の契約をコア・テストへ対応づける。既存と差がある箇所を変更前に記録する。
3. 定義JSON／manifestを型付きデータへ変換し、不正ID・画像・座標を拒否する検証を作る。
4. 1敵の本体＋4部位と5人の仮表示でイベント順・破壊・停止／短縮を確認する。
5. 人物1人・敵1体・背景1セットのオリジナル2D品質を確認する。
6. 箱庭1区画・家具3種・人物3枠、ADV線形命令・回想を接続する。
7. 必要な保存版変更と変換表を作り、正常バックアップ・失敗・再試行を検証する。
8. Windowsビルド・オフライン起動・保存復旧・1080p／720pを確認する。
9. 一周のプレイ時間・詩収集・素材量・工数を測り、正式値と量産へ進む。

## 3. 完了条件

[契約受入試験](spec-implementation-contracts.md)10章、[2D戦闘](spec-2d-battle-presentation.md)、[箱庭・ADV](spec-2d-garden-and-adv.md)、[素材品質](spec-2d-assets-and-acceptance.md)の確認結果を記録する。正式確率と画像尺はTBDのまま仮データで契約試験を進められるが、正式バランス合格とは扱わない。

実装のCoreから描画APIへ依存させず、UIがHP・詩・報酬・解放を直接変更しない。Unityコード・素材・セーブの変更を文書の作成で完了扱いにしない。3Dモデル／リグ／FBX検証と旧ブラウザの復元・照合は必須条件にしない。

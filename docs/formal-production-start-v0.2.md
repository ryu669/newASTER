# 正式版着手パッケージ v0.2

本書は、[ゲーム要求仕様 v0.2](game-requirements-v2.md)を正式版制作へ移すための開始条件、構成、最初の作業順を定める。旧資料の候補を再採用するものではなく、現行仕様を優先する。

## 1. 着手判定

| 項目 | 状態 | 根拠／次の行動 |
| --- | --- | --- |
| 現行要求仕様 | 準備済み | v0.2と詳細仕様を最新・優先として登録済み |
| 最初の完成単位 | 準備済み | 1巨神獣＋5人＋詩＋箱庭＋成長の縦切りを定義済み |
| ルールコア | 準備済み | 描画非依存の戦闘・進行コアと36件の回帰試験がある |
| 開発環境 | **準備済み** | Unity 6000.6.3f1 + Windows Build Supportで`game/unity/`を初期化し、2026-09-27に空のWindowsビルド成功を確認 |
| 正式コンテンツ | 未着手 | 1体目の固有名・5人の採用人物・本文・モデル・音はTBD。仮試作人物を自動流用しない |
| Unity実装層 | 未着手 | `game/unity/`にプロジェクトを初期化し、C#から描画非依存コアを呼ぶ |

したがって、正式版の**仕様・ルールコア・Unityプロジェクト・Windowsビルド・制作計画は着手可能**である。正式コンテンツの量産は、縦切りの戦闘時間・詩取得テンポ・UI観察を通してから開始する。

## 2. 技術方針

- 配布対象：Windows、オフライン専用。
- 初期エンジン：Unity 6000.6.3f1 + Windows Build Support。空のWindowsビルド成功を確認済み。URPの採用は、最初の描画縦切りで確認して固定する。
- ルール層：`game/core/`のように描画と分離する。Unity側のGameObject、Animator、Timeline、入力イベントをゲーム判定へ直接渡さない。
- データ層：巨神獣、部位、ヒロイン、スキル、詩、物語、家具、オーパーツをIDで参照する定義データにする。ユーザーセーブは定義データを複製せず、IDと進行だけを保存する。
- 表示層：戦闘演出・万物の書・箱庭はルールコアのイベントを読む。表示短縮やフレームレートがHP、報酬、詩、乱数結果を変えてはならない。

## 3. リポジトリの正式構成

```text
game/
  core/                 # 描画非依存のルール検証。現時点は縦切りJS実装
  data/                 # 検証用定義と、将来の正式データのスキーマ
  unity/                # Unityプロジェクト（初回セットアップで作成）
    Assets/Game/Scripts/Core/
    Assets/Game/Scripts/Presentation/
    Assets/Game/Data/
    Assets/Game/Tests/
    Assets/Game/Scenes/
  README.md             # 起動・ビルド・検証手順
docs/
  game-requirements-v2.md
  spec-*.md
  vertical-slice-spec-v0.2.md
```

既存の`src/`、`tests/`、`tools/`はブラウザ試作と移植照合のため残す。正式版のUnityコードと混在させない。

## 4. 最初の10作業

1. `Core`、`Presentation`、`Data`、`Tests`のasmdefを作る。`Core`からUnity APIへ参照できないことをビルドで確認する。
2. `bookmarkId / subjectId / faceId`を持つ万物の書の状態機械を作る。
3. 5人・本体・4部位・Lv1〜50・Lv45最強技を持つ縦切りのC#ルールコアを作る。
4. シード固定の戦闘ログと、部位破壊・チェイン・勝利報酬のテストを移植する。
5. 進行コア（詩、物語、テラフォーミング、オーパーツ）と原子的セーブを接続する。
6. 万物の書の4しおり、召喚、戦闘結果、本の閲覧を仮UIで一周させる。
7. 1体目と5人を決め、固有スキル、部位、大技、詩対応表をデータ化する。
8. 箱庭1区画、家具3種、好感度イベント1本を接続する。
9. 縦切りプレイテストの計測値を記録し、Gate 1の合否を判定する。

## 5. 初回ビルドの完了条件

- Unity Editorを開き、警告・エラーなしで空のWindows実行ファイルを作れる。**2026-09-27に確認済み。**
- 生成物はネット接続を要求せずに起動・終了できる。
- ルールコアのテストと、ブラウザ試作の既存テストがともに通る。
- 最初のシーンで、ゲーム名、バージョン、セーブ領域、開発ビルドであることを確認できる。

失敗した場合はエンジン版、URP、Windows Build Support、ライセンス、出力ログを記録し、ゲーム仕様とは分けて解決する。素材や正式人物の制作を先行させない。

### 2026-09-27 初期化・ビルド結果

- 実行対象：Unity 6000.6.3f1、バッチモードで`game/unity/`を新規作成。
- 結果：`game/unity/`にUnityプロジェクト（Assets、Packages、ProjectSettings）を作成できた。ローカル生成物（Library、Logs、UserSettings）はGit管理外とした。
- ライセンス：初期化時の認証警告は残ったが、空ビルド時にはUnityがエンタイトルメントを解決できた。現時点でライセンスはブロッカーではない。
- Windows Build Support：追加後、最初の失敗はビルド対象シーンが0件だったことによる。`Assets/Game/Scenes/Bootstrap.unity`を追加して解消した。
- ビルド：`game/Builds/smoke/newASTER.exe`を含むWindowsプレイヤーを生成し、Unityログの`Build Finished, Result: Success.`を確認した。生成物はGit管理外。

## 6. 制作開始後に毎回守る品質条件

- 新しい巨大な機能は、定義データ、保存、画面表示、最低1本の自動試験を同じ変更で追加する。
- 巨神獣、ヒロイン、詩、家具、イベントは表示名で相互参照せず、安定IDを使う。
- 既存セーブに読み込めない変更は、移行処理とバックアップを同時に用意する。
- 参照作品の素材、録画、抽出画像、データ本体をリポジトリへ入れない。正式本文・モデル・音は権利を確認した制作物だけを登録する。
- 計測した結果が縦切りの目標を満たさない場合、コンテンツ量を増やす前にルール・UI・報酬を調整する。

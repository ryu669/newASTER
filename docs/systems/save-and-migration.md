# 保存・原子性・移行・未知データ

更新：2026-10-02。状態：現行仕様。版はGit履歴で管理し、ファイル名に版番号を付けません。仕様整理のみで実装完了を意味しません。

## 保存と移行契約

既存CampaignSaveV2へ追加するか別版へ移すかはローカルの現在形式確認後に確定する。新しい自由座標・ADV既読を使う場合は次の論理項目を版管理する。

既読はsceneId＋scriptVersion＋lineIdの複合キー。本文差替時の既読維持はID対応表で判断し、indexだけで移行しない。報酬IDはbattle／event／gachaの種別付き安定IDで保存する。

一時ファイルへ全payload書込み→再読込検証→正常現行をbackupへ保全→現行を置換。失敗時はメモリ進行も保存前状態へ戻し、同じtransactionIdで再試行する。未知の将来版は上書き拒否し元ファイルを保持。未知家具／人物は保持して未配置へ退避し通知する。

旧固定スロットからの変換はslotId→gardenId／zoneId／接地座標の明示表を用意する。変換表がない版は推測で移行せず、旧版の保持／バックアップ復旧を提示する。今回の文書更新では既存セーブの版番号を変更しない。

## 報酬トランザクション

保存状態を、定義データとプレイヤー進行に分離する。定義のID変更・削除はセーブ移行表なしに行わない。

- `claimedBattleRewardIds`で同じ終了戦闘からの詩・関連解放、および勝利時だけの素材、テラフォーミング、交流権、レリックハント報酬の二重確定を防ぐ。
- 章解放は詩追加と同じ保存単位、イベント解放は読了・好感度・報酬と同じ保存単位にする。
- 失敗時は書込み前の正常セーブを残し、再試行は同じ`battleId`を二重加算しない。

勝利確定タイミングは[戦闘仕様](battle.md)に従う。型は共通データ契約を参照する。

## 操作トランザクションと復帰

全進行変更は単一書込み列で直列化する。transactionIdは操作の確認入力時に発行し、種類・対象・内容版・基準revision・抽選済み結果を持つ。新規変更を計算するのは一度だけ。保存失敗後は表示を最後の正常payloadへ戻し、同じセッション内の保留transactionを保持する。再試行はその結果を再保存し、再抽選しない。確定後の同ID再送は確定済み結果を返し、費用も報酬も再適用しない。基準revisionが変わった未確定操作は実行拒否してプレビューから作り直す。

保存成功は現行ファイルの置換と検証完了を指す。クラッシュ復帰時は現行が正常なら最優先し、同saveIdの正常backupへだけ復旧する。tmpを進行セーブとして自動採用しない。現行が将来版ならbackupへ黙って巻き戻さず上書き拒否。両方不正なら元ファイルを保持し復旧不能を通知、新規開始は別saveIdとする。物理的な停電耐性はローカルの書込み方式確認と障害試験で評価する。

未確定transactionは初回契約ではセッション内だけに保持し、再起動後に再開しない。現行に確定済みなら成果を復元、未確定なら正常保存以前の所持量へ戻る。確定IDとpayload更新は同一ファイルに保存し、片方だけ成功しない。旧claimedBattleRewardIdsは論理的には種別付きclaimedTransactionIdsのbattle分に対応させるが、現在の保存形式への適用は明示移行表の作成後とする。

解放・読了・所持などの集合は重複のないID配列で交換する。未知IDは削除せず保持し、条件達成の根拠として使わない。定義が復帰したら再検証して利用可能にする。未知人物・家具の退避領域も保存対象に含め、往復保存で失わない。

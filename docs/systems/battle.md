# 戦闘・部位・ジョブ・独立自動チェイン

更新：2026-10-02。状態：現行仕様。版はGit履歴で管理し、ファイル名に版番号を付けません。仕様整理のみで実装完了を意味しません。

## 定義範囲

戦闘・部位・スキル・ジョブ・チェイン・勝敗確定の唯一の詳細定義元です。時間の計算は[battle-timing](battle-timing.md)、型は[共通データ](../data/contracts.md)、表示は[2D戦闘](../presentation/battle.md)を参照します。

## 戦闘開始から確定まで

### 出撃前

1. プレイヤーは2Dマップまたは万物の書の巨神獣ページで、解放済みの巨神獣を選ぶ。
2. Lv1〜50を選択する。初回はLv1を初期選択する。前回選択Lvを記憶してもよいが、再召喚時に変更可能にする。
3. 所持ヒロインから異なる5人を編成する。5枠未満で開始可能にするかはTBD。開始可能なら空枠はチェイン参加者にならない。
4. 各人に装備の樹で選択中の武器とオーパーツを反映し、部位、報酬種別、Lv、Lv45以上の最強技警告を出撃前に表示する。
5. 出撃確定時に`battleId`、対象ID、選択Lv、編成スナップショット、乱数シード、開始時刻を作る。戦闘中に編成・装備・選択Lvを変更できない。

撤退は許可するが、勝利専用の討伐、ページ解放、素材、テラフォーミング、交流権を付与しない。敗北も同様。ただし巨神獣詩・対応ヒロイン詩と関連章解放は勝敗・撤退にかかわらず確定する。リトライは新しい`battleId`で開始する。

### 戦闘状態

通常は`Preparing → ScheduledEvent → PlayerCommand → Resolving → ScheduledEvent`。詠唱発動／敵行動はScheduledEventから解決する。チェイン対象コマンドの発動解決後は`Resolving → ChainChecking → ChainExecuting → ChainChecking`を必要回数実行し、起点への戻り接続成功ではFullChainExecutingへ移行し、終了後にScheduledEventへ戻る。どの解決段階でも勝敗確定は`ResultPending → Closed`へ進む。結果理由はvictory／defeat／retreatとして別管理する。

- `Preparing`：対象、部位、各戦闘者の初期HP・リソース・パッシブを生成する。
- `PlayerCommand`：行動可能なヒロイン、選べる3スキル、対象、コスト、予測値、チェイン補正を表示する。未確認のジョブ固有操作をこの状態の外で自動処理にしない。
- `Resolving`：入力済みのスキルを、対象確認→コスト→命中／状態判定→ダメージ／回復→部位破壊→追加効果の順で一度だけ処理する。
- `EnemyAction`：生存部位を含む行動表から実行可能な行動を判定する。大技ゲージが最大なら大技を優先する。破壊済み部位に依存する行動は除外または個体定義の代替行動へ置換する。
- `ResultPending`：勝敗を確定した戦闘は以降の行動と報酬計算を停止する。詩取得を含む終了結果をこの状態から一度だけ保存トランザクションへ渡す。勝利専用報酬はvictory時のみ追加する。

休止・結果確定・再起動の境界は本書の「勝敗確定と演出終了」を適用する。戦闘途中再開は初回未対応。一つのbattleIdで報酬を二重確定しない。

## 巨神獣・部位・Lv

### 定義データ

- `pageOrder`は万物の書・2Dマップ双方の順序であり、解放条件は[世界記憶仕様](../world/world-memory.md)を参照する。最終個体の全初回討伐条件を直前一体だけの条件へ置換しない。
- `parts`は本体を除く4〜6部位。部位HPが0になったら`broken=true`に固定し、同じ部位の破壊効果を再発火させない。
- 本体HPが0なら勝利。部位をすべて破壊しても本体HPが残る場合は勝利にしない。
- `levelScalingRuleId`は数式をデータとして参照する。HP、攻撃、防御、状態耐性、報酬、テラフォーミングがLvでどう変わるかは個体別に明示する。Lv45〜50だけ最強技可否を追加する。

### 大技ゲージ

巨神獣の大技は`current / max`で画面に常時表示する。行動ごとの増加量、最大時の消費量、満タン時に即発か次行動時発動かは`actionTableId`に記録する。大技を止める部位、必要な破壊タイミング、破壊後のゲージ処理は個体ごとに`breakEffectId`で定義する。最強技は`selectedLevel >= 45`で候補に加える。Lv45未満には最強技用の予兆を表示しない。

## ヒロイン、スキル、ジョブ

### 定義データ

- 一人のヒロインには必ず3つの固有スキルを持たせる。ヒロイン個別のスキルは、ジョブ名だけで自動生成しない。
- `chainEligible=false`のスキルを置く必要が出た場合は、理由とUI文言を仕様化する。現時点では全スキルの可否はTBD。
- ヒロイン特性、武器、オーパーツは威力、属性、状態異常、資源、耐性等を変えられるが、**チェイン発生率を直接・間接に増やしてはならない**。データ検証で`chainRate`を含む効果種別を拒否する。

### ジョブの実装境界

13ジョブ全員に、他ジョブと区別できる`resourceType`または`commandRules`を必須とする。現時点で確認済みのスレイヤー（ファイター系）だけは以下を設計要件とする。

| ジョブ | 確定するUI・状態 | TBDとして残すもの |
| --- | --- | --- |
| スレイヤー | ブースト球表示、通常／捨て身モード、球の保持・消費選択、ラストリゾートゲージと発動予告 | 球数上限・増加式、モード補正、赤球、ラストリゾートの最終性能、全スキルの球消費 |
| 残り12ジョブ | ジョブ固有リソースまたはルールを持つこと | 個別リソース名、UI、取得・消費、Auto、数値。原作確認後に別紙で確定 |

原作演習のスレイヤーにおける速度+50%・クリティカル+50%・3ターンは記録値であり、`JobDef`の初期値として固定してはならない。

## 独立チェイン

### 固定行動と接続

2026-10-02ユーザー確定：チェイン接続を確率判定し、成功後はユーザー操作なしで当該キャラ固有の固定行動を実行する。2人目以降すべて同じ。チェイン参加・実行順は通常の速度順・次コマンド予定から独立する。旧 `timeline-sequential-v1` は廃止する。

1. chainEligibleなコマンドの発動を解決し、戦闘が継続していればチェインを開始する。コマンド選択キャラを起点の1人目として数える。詠唱付きコマンドは詠唱開始時に判定せず、発動時だけ判定する。中断・不発では判定しない。非攻撃スキルの開始可否は個別chainEligibleでTBD。
2. 戦闘開始時の編成順で起点の次枠から走査し、行動可能・未参加の次のヒロインを候補にする。後続接続は直前参加者の次枠から同じ走査を行う。末尾の次は先頭へ回り、起点へ戻ったら起点への接続判定を行う。ただし起点以外の参加者がいない場合は候補なしで終了する。空枠・戦闘不能・行動不能・参加済み（戻り判定の起点を除く）は飛ばし、飛ばした枠では乱数を消費しない。速度、次行動tick、通常の未行動フラグは参照しない。ユーザーには候補を選ばせない。
3. 接続率を確率判定する。失敗ならそのチェインを終了し、不参加候補の固定行動は実行しない。無効候補では抽選しない。
4. 成功なら候補本人のChainActionDefを解決する。スキル選択・対象確認・確定ボタンを挟まない。対象はtargetRuleIdで自動決定する。人物ごとの行動は決まっており、通常の3スキルから毎回選択する方式ではない。
5. 2人目以降も同じ候補決定→接続抽選→固定行動を繰り返す。通常周回の異なる参加者は最大5人、各人一度。起点への戻り接続に成功すると下記のフルチェインへ移行する。勝敗確定・候補なしでも終了する。
6. チェイン終了後に通常の予定列へ戻る。チェインが別人物の通常行動を待ったり、通常予定が来たことを接続条件にしたりしない。

ユーザー確定：チェイン行動とコマンド行動は相互に影響しない。チェインによる資源消費・獲得・条件参照はなく、ジョブ資源・通常待機・詠唱予約を変更しない。通常コマンドの実行／資源不足／待機／詠唱中を理由にチェイン行動を変更・禁止しない。詠唱中でも行動不能でなければ参加し、元の詠唱予約は保持する。固定行動の威力・効果・自動対象ルールは人物別TBD。ヒロイン固有の固定行動で威力や効果を変えても、チェイン率の強化は禁止する。

チェイン一連の解決中は通常予定列を進めず、敵・他の通常行動を差し込まない初回の暫定実装契約とする。演出時間を論理tickへ加算しない。通常次行動tick・castAt・待機量はチェインの前後で不変。部位破壊だけでは自動終了せず、次の固定行動の対象ルールで再検証する。勝敗後の追加行動・抽選は禁止。

例：Aの起点攻撃→Bへの接続成功→B固有行動を自動実行→Cへの接続成功→C固有行動を自動実行→次接続失敗で終了。この間にユーザーはB/Cのスキル・対象を選ばない。通常の次行動予定がDであっても、B/Cへの接続条件にはならない。

### 補正と抽選の寿命

ランダム補正は起点のコマンド受付で一度生成・表示し、チェイン終了まで同じmodifierBatchIdを保持する。起点コマンド確定時に破棄して後続自動行動へ適用不能にしない。+10%および最大2ヒロインへの+5%の要件は維持する。

2026-10-02ユーザーより確率調整を委任。初期採用値は下記に従う。旧方式の「現在行動者の補正だけを使う」「他人物の補正を次受付まで捨てる」を採用しない。接続ごとに適用元と最終率をログへ記録し、表示と抽選を一致させる。

確率はbp整数0〜10000、100bp=1%。各接続は一度だけ抽選し、候補・抽選値・成功／失敗・固定行動IDを保存する。描画・ヘルプ・停止復帰・演出短縮で再抽選しない。再現ログはchainIdとstepIndexを追加する。候補選出は編成順の決定処理であり乱数を使わない。

### チェイン確率・補正の初期調整値

- 基本接続率は全人物共通50%（5000bp）。通常接続と起点への戻り接続に同じ式を使う。人物・ジョブ・Lv・覚醒・重複・装備・好感度による率の加算はない。
- 起点のコマンド受付で、3スキルの各枠へ独立に25%の確率で `CHAIN +10%`（1000bp）を付与する。0〜3枠へ付与されうる。確定した起点スキルの補正だけをそのチェイン全接続へ保持し、後続固定行動に別のスキル抽選をしない。
- 同じ受付で50%の確率で「最大2キャラまで累積+5%」枠を付与する。成功時は開始編成から異なる2枠を均等抽選し、それぞれを+5%対象として表示する。編成が2枠未満なら存在する枠だけ。行動不能かどうかで付与先を再抽選せず、不能者が参加しなければ累積しない。
- +5%対象本人が通常周回へ実際に参加すると、その後の接続率へ500bpを加算する。起点が対象なら最初の判定前に加算。後続本人は接続成功して固定行動を実行した後に加算するため、本人への接続判定には自分の+5%を先取りしない。異なる最大2人、一人一回、計1000bpまで累積する。起点への戻りで二重加算しない。
- 接続率は `5000 + 起点スキル補正(0/1000) + 参加済み対象の累積補正(0/500/1000)` bp。範囲50〜70%。補正は一連のチェイン終了で失効し、次の通常コマンドへ持越さない。詠唱起点は受付時の補正を予約に保持し、発動時に再付与しない。
- 接続判定は偏りのない整数 `[0,9999]` を一回引き、値が率未満なら成功。50%なら4999は成功、5000は失敗。フルチェイン追加一周は既定どおり再抽選なし。
- 3スキルの付与抽選→累積枠の有無→付与先の均等抽選の順にログへ記録する。付与失敗時は付与先抽選を行わない。ヘルプ・プレビュー・入力取消で付与をやり直さない。付与先の選出乱数と接続乱数はpurposeを区別する。

例：起点Aに+10%、累積対象A/Cなら、Bへの判定65%、Cへの判定65%、C実行後のD/E/Aへの判定70%。Cが不能ならCを飛ばし累積は65%のまま。全員行動可能・補正なしの5人到達率は `0.5^4=6.25%`、戻り成功までのフルチェイン率は `0.5^5=3.125%`。全接続70%の場合の上限は16.807%で、通常の補正抽選込みの平均率とは区別する。

この数値は本作の初期調整案。人物固有の威力・効果を仮定して最終バランス合格とはしない。実戦で接続回数、フルチェイン率、追加ダメージ比率、演出込みの周回時間を記録し、共通確率だけを調整する。

### 人物固有行動の定義責任

ユーザー確定：固定行動の威力・効果・自動対象・演出はヒロイン定義側で決める。各 `HeroineDef.chainActionId` から本人の `ChainActionDef` を参照し、ジョブ名や通常3スキルから推測生成しない。共通チェイン仕様が決めるのは接続・順序・補正・非干渉・終了だけ。未定義の人物は正式データとして受け入れず、検証用仮行動はplaceholder定義へ分離する。

## 勝敗確定と演出終了

コアが勝敗を判定すると`resultPending`にして後続の攻撃計算・乱数・行動予約を停止する。直前までに確定したイベント列は戦闘終了イベントを含めて順次表示する。コアが勝利済みでも、先行する確定攻撃の演出を勝手に捨てない。最後のイベント後に結果画面を開く。

スキップは残る装飾のみを省略し、最終スナップショットへ同期して結果画面へ進む。計算を再実行しない。撤退は`resultPending`到達前にだけ確定可能。計算上の勝敗が確定済みなら撤退ボタンを無効にし、演出スキップを提供する。撤退確定は未再生演出を破棄し、取得詩の保存・結果確認後に拠点へ戻る。勝利専用報酬は付与しない。

勝利・敗北・撤退の終了結果はresultPending到達時に一度だけ同じbattleIdで保存する。詩は全終了理由で確定し、勝利専用報酬はvictoryだけに含める。保存成功後に結果を確定表示し、失敗時は報酬全体を保留して再試行する。演出終了や結果画面を開き直すことで報酬を再生成しない。結果表示前に終了しても正常保存済み報酬は次回進行へ残る。旧未確定セッションの再開は行わず、戦闘途中は拠点から再挑戦する。

### 相互非干渉の適用境界

コマンドの資源獲得・消費、使用回数、クールダウン、使用後待機、詠唱開始／終了に紐づく効果をチェインから呼ばない。逆にコマンド固有のモード・蓄積・使用履歴で固定チェイン行動を置換・強化しない。通常コマンドの継続補正は発動済み起点のchainContextとして保持し、詠唱中の別コマンド受付で上書きしない。

HP・部位HP・破壊・勝敗は共通の戦闘状態であり、チェインの攻撃結果を反映する。「相互影響なし」を敵HPや勝敗を別管理する意味にはしない。行動不能の判定は各候補走査時の最新状態で行い、その人物の通常行動を未消化でもチェイン参加は可能。チェイン行動を新たな通常コマンド起点とみなさず、同じchainIdの次接続へ進む。

### フルチェイン：起点接続後の追加一周

ユーザー確定：チェインが編成順で起点へ戻り、その接続判定に成功した場合、フルチェインとして起点から追加一周の固有チェイン行動を実行する。起点への接続失敗なら追加行動なしで終了する。以前の「5人到達で終了」「同一人物は全過程で一度」をこの規則で置き換える。

例：`A（コマンド発動）→B→C→D→E→A（戻り接続成功）` の後、`A、B、C、D、E` がそれぞれ固有チェイン行動を一回ずつ自動実行する。戻り成功時のAは追加一周の先頭であり、別のA行動を重ねて二回実行しない。全員行動可能なら、起点コマンド1回＋通常接続行動4回＋追加一周5回で計10回となる。

追加一周はフルチェインの成功報酬として実行し、途中の各接続を再抽選しない。追加一周の末尾で必ず終了し、再度起点判定・追加周回を行わない。入力・資源・通常予定列・詠唱予約との非干渉は通常チェインと同じ。

行動不能者を飛ばす既定規則は戻り判定と追加一周でも維持する。起点が戻り時点で行動不能なら戻り接続を抽選せず終了。追加一周は起点から編成を一巡し、各枠の実行直前に行動可能性を再検証して不能者を飛ばす。通常周回で飛ばした枠も追加一周ではその時点の状態で判定する。途中で勝敗が確定したら残りの行動は実行しない。部位破壊時の自動対象規則は各固定行動で再検証する。
